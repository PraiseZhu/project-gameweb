# 第 3 项：页面骨架

状态：✅ 已定（2026-11-12）。长滚动页的 fix/ 规则另定

## 3.1 整页分几大块

**开发侧（cn.html）：**
- 顶部导航 `header.site-header`：**全页只有一份**，里面放 logo、导航按钮、社媒、语言切换。
- 中间 `main.onepage`：6 屏叠在一起，一次显示一屏。
- 底部底栏 `.footer-strip`：**全页只有一份**，里面放“下一屏 / 返回首页”按钮。
- 前景装饰层 `.foreground-track`：独立一层，每屏一组装饰，跟着当前屏切换。
- 末屏挂公司统一页脚。

**Gameweb（线上页）：**
- 导航**每屏各有一份**：6 层导航，每层 6 个按钮，共 36 个按钮，切屏时跟着换。
- 每屏内部分为满铺背景、钉视口层、内容画布、前景几层。
- 没有统一页脚。

**历史草案（已被下方 3.1a～f 取代，不采用固定四块）：**

| # | 规则 | 原样 / 优化 | 检查方式 | 信息来源 |
|---|---|---|---|---|
| 3.1 | 整页固定分成四块：顶部导航（全页一份）、屏幕区（N 屏）、底栏（全页一份）、前景装饰层（每屏一组）。末屏挂统一页脚。设计稿每屏都画了一份导航、底栏时，只取一份，不按屏复制 | 原样 | 机器：页面里 `header`、`.footer-strip` 各只能有 1 个；屏数等于设计稿 `sec/` 数 | 固定模板 + 设计稿 |

### 用户修正（2026-11-12）

按开发侧的形式分块，但**块的种类和数量不固定**：可能是侧边栏导航而不是顶部导航，可能没有底栏，可能没有前景层。要按具体设计画面分块。追问：怎么保证？按什么分？命名能体现吗？开发侧有什么区分要求？

### 查证

- **开发侧没有成文的分块规则**。只有这一个样本，块是 AI 看画面分的。
- **设计稿里已有的命名可以直接对应**（现行命名规范）：
  - `sec/`：屏幕分区，对应屏幕区里的每一屏；
  - `fix/`：视口固定悬浮层，规范原文就写着“侧边导航、返回顶部”，对应导航、底栏、侧边栏这类固定块；
  - `fix/` 的可选参数 `@from=N`：滚到第 N 屏才出现。
- **本稿实测**：
  - PC 有 `fix/顶部导航通栏` ×6（每屏画了一份）、`fix/底部固定背景` ×5（第 2～6 屏才有）；手机有 `fix/顶部导航栏` ×6、`fix/底部装饰` ×6。
  - 底栏只画在第 2～6 屏，正好对应开发侧“首页不显示底栏”。
  - **前景装饰没有统一命名**：PC 写法有 `img/前景装饰` ×3、`img/前景素材`、`img/装饰前景` 三种，手机端没有任何标记。但开发侧手机端其实有前景图（`foreground-*-mobile.png`）。机器认不出来。

### 规则（3.1 修订，✅ 已定 2026-11-12）

| # | 规则 | 检查方式 | 信息来源 |
|---|---|---|---|
| 3.1a | 分块**只按命名**，不看画面猜 | 机器 | 设计稿命名 |
| 3.1b | 屏幕区：每个 `sec/N` 一屏，必须有 | 机器：屏数等于 `sec/` 数 | 设计稿 |
| 3.1c | 固定块：每个**不同名**的 `fix/` 是一块。多屏里同名的 `fix/` 合并成一份。放顶部、侧边还是底部，从坐标判断。哪几屏显示，看它画在了哪几屏里，或者看 `@from=N` | 机器 | 设计稿 |
| 3.1d | 前景层：需要在命名规范里新增统一的前景标记（写法留到改命名规范时定，见 F7）。有标记才生成前景层，没有就不生成 | 机器 | 设计稿 |
| 3.1e | 统一页脚：设计稿里不画，按 6.4 预留接入口，开发决定是否接入并填写配置（17.4） | 机器 | 开发配置 |
| 3.1f | 稿上没有的块就不生成，不套空壳 | 机器 | 设计稿 |

### 适用范围提醒（用户 2026-11-12）

3.1c“`fix/` 画在哪几屏，就在哪几屏显示”**只适用于整屏切换页（onepage）**。
瀑布流长图页（长滚动页）里可能只画 **1 个** `fix/`，但它要**一直钉在屏幕上**。长滚动页的 `fix/` 规则以后单独定；现行命名规范里的 `@from=N`（滚到第 N 屏才出现）可以作为参考。

## 3.2 每一屏内部怎么分层（✅ 3.2a～c 已定 2026-11-12）

**开发侧：**
- 满铺背景 `.fullscreen-bg`：铺满整个屏幕，按比例裁切（cover），电脑和手机各用一张；
- 内容舞台 `.page-stage`：固定 19.2×10.8rem（即设计稿 1920×1080），**在屏幕中间居中**，所有内容都放在里面；
- 标题区 `.section-header`：标题文字（`h2`）加背后的水印图；
- 业务模块放在舞台里，标题区下面。

效果：屏幕比例和设计稿不一样时，背景照样铺满，内容保持设计稿比例居中，两边多出来的部分只露背景。

**Gameweb：** 每屏也分满铺背景层和内容画布，内容画布按设计宽度整体缩放。思路相近，但内容是 1235 个绝对定位块。

**已定规则：**

| # | 规则 | 原样 / 优化 | 检查方式 | 信息来源 |
|---|---|---|---|---|
| 3.2a | 每屏分两层：满铺背景（cover 裁切）＋ 内容舞台（按设计稿比例，居中） | 原样 | 机器：多比例视口下背景无留白，舞台中心等于视口中心 | 固定模板 |
| 3.2b | 满铺背景取设计稿里该屏的 `bg/`（或 `kv/`）；电脑和手机各取各的 | 原样 | 机器 | 设计稿 |
| 3.2c | 屏里有标题时，标题统一放在标题区：真文字标题加装饰底图；整页只有首屏一个 `h1`，其余屏标题都是 `h2` | 原样 | 机器：`h1` 只有 1 个，每屏最多 1 个 `h2` | 设计稿 |

## 3.3 内容层和背景层里面怎么再分（✅ 已定 2026-11-12）

用户的理解：内容层是一个大模块，里面再分小模块；背景层大多是一张静态图；都按设计稿命名区分。

**开发侧实际结构（第 3 屏“区域赛果”为例）：**

```
内容舞台 page-stage
├── 标题区 section-header（水印图 + h2“区域预选赛”）
├── 赛区切换 region-tabs（3 个按钮）
└── 赛区面板 region-panel ×3
    └── 排行卡 rank-card ×4
        └── 排行行 rank-row ×6（底图 + 皇冠 + 名字 + 分数）
```

可见内容层**不止两级**：舞台 → 大模块（赛区面板）→ 小模块（排行卡）→ 重复项（排行行）→ 元素（名字、分数）。

**背景层：**
- 大多数情况是一张静态图（`bg/`）。不同屏可以共用同一张，例如开发侧手机端第 3、4 屏共用 `bg-qualifiers-mobile.jpg`。
- 例外：
  - 首屏有 KV 视频 `kv_{语言}.mp4`，视频里自带对应语言的 slogan。视频不在设计稿里，正式素材及接入按第 6.4、13、17 项归开发。
  - `kv/` 视差分层：背景、角色、前景各一层（现行命名规范已有）。
- 背景层不再细分模块，按 `bg/`、`kv/` 前缀认。

**已定规则：**

| # | 规则 | 检查方式 | 信息来源 |
|---|---|---|---|
| 3.3a | 内容层按命名分模块，**模块可以多层嵌套**（大模块里套小模块，小模块里有重复项和元素）。每一层都由命名决定，不按画面猜。模块名的写法见 F1 | 机器：页面结构的层级和命名层级一致 | 设计稿命名 |
| 3.3b | 背景层不分模块，按 `bg/`、`kv/` 前缀认。通常一张静态图；`kv/` 可以有多层 | 机器 | 设计稿命名 |
| 3.3c | 视频背景不在设计稿里，由开发配置提供；Gameweb 只预留接入口（第 6.4、13、17 项） | 机器 | 开发配置 |
