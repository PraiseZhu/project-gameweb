# 第 11 项：字体

状态：✅ 已定（2026-11-13）

## 开发侧做法（实测 ews2026/css/font）

| 字体 | 文件 | 大小 | 用在哪 |
|---|---|---|---|
| Alimama ShuHeiTi（阿里妈妈数黑体）Bold 700 | `AlimamaShuHeiTi.ttf` | 1.3MB | 简中标题等展示文字 |
| Bebas Neue Regular 400 | `BebasNeue-Regular.ttf` | 56KB | 数字、英文标题 |
| Noto Sans（可变字重） | `NotoSans-Variable.ttf` | 2.0MB | 英语正文 |
| Noto Sans JP | `NotoSansJP-Variable.ttf` | 9.1MB | 日语 |
| Noto Sans KR | `NotoSansKR-Variable.ttf` | 9.9MB | 韩语 |
| Noto Sans HK | `NotoSansHK-Variable.ttf` | 11.4MB | 繁中 |

- 每个 Noto 字体旁边放一份 OFL 许可证；字体都来自 Google Fonts 官方仓库；
- 全部用 `@font-face` + `font-display: swap`（字体没加载完先用系统字显示）；
- 简中正文没有本地字体，靠系统字（`Noto Sans SC`、微软雅黑、苹方）兜底；
- **整套字库原样放，没有裁剪**。README 原话：“保留完整字库以支持后续接口文案；单份日韩繁字体约 9～12 MB，首次加载体积较大。”另有一份 `BebasNeue.otf` 是重复文件，没有引用。

来源和许可证、`font-display: swap`、按语言加载等要求以本项已确认条款为准；字体变量沿用第 5 项。不能将这些具体确认扩大成“开发有做法就自动采纳”的全局授权。

## Gameweb 做法

字体按页面实际用到的字裁剪成小文件（`*.pack.woff2`），14 个文件共约 1.1MB。但有两个问题：文件格式标错（woff2 写成 truetype）；500 和 700 字重指向 400 的文件，浏览器只能用假粗体。

## 11.1 要不要裁剪字库（✅ 已定 2026-11-12：选 A，完整字库，照开发侧）

- **A. 照开发侧：完整字库。** 后台以后改的文字一定能显示；代价是日、韩、繁中页首次打开要多下载 9～12MB，手机流量下明显变慢。
- **B. 裁剪成小文件（优化）。** 只保留页面上实际出现的字，体积可以降到几百 KB。但第 0 项已定“运营可在后台改文字”，后台新填的字如果不在裁剪范围里，会退回系统字显示，字形对不上。
- **C. 折中（优化）。** 页面固定文字用裁剪字体；后台可改的字段改用完整字库，或者接受这些字段退回系统字。

## 11.2 字体文件从哪来、怎么放（✅ 已定 2026-11-12）

开发侧做法：
- Noto 系列（英、日、韩、繁中）来自 Google Fonts 官方仓库，每个字体旁边放一份 OFL 许可证（`NotoSans-OFL.txt` 等）；
- 阿里妈妈数黑体、Bebas Neue 放在同一目录，没有附许可证文件；
- 全部放在 `css/font/`，用原始格式（`.ttf`），没有转成更小的 `.woff2`；
- 有一份没被引用的重复文件 `BebasNeue.otf`。

已定内容：放在 `css/font/`；每个字体都附许可证或来源说明（补上开发侧缺的两个，小优化）；用原始格式；没被引用的字体不进交付包。

## 11.3 字体怎么加载、缺字时用什么（✅ 已定 2026-11-13）

开发侧做法：
- 用 `@font-face` 声明，统一 `font-display: swap`：字体没下载完时先用系统字显示，下载完再换上；
- 简中页只声明阿里妈妈数黑体（标题）和 Bebas Neue（数字）；外语页另外加载 `locales.css`，里面声明对应语言的 Noto 字体。浏览器只下载当前语言实际用到的字体；
- Noto 是可变字重字体（一个文件包含 100～900 所有粗细），所以没有“假粗体”问题；
- **简中正文没有放本地字体**，按顺序用系统里的 `Noto Sans SC` → 微软雅黑 → 苹方。不同电脑、手机上看到的正文字体会不一样。

已定内容：
- 加载方式照开发侧：`@font-face` + `font-display: swap`；按语言只加载当前语言用到的字体；用可变字重或真实字重文件，不允许假粗体；
- **放什么字体，按设计稿来**：设计稿（含各语言稿）用到的每一种字体，都要放对应的完整字体文件（11.1），存放按 11.2。简中正文如果稿上用了 Noto Sans SC，就放 Noto Sans SC 的文件，不像开发侧那样靠系统字。
- 配套：Gameweb 已有字体登记册 `skills/yise-web-ui/fonts/registry.json`，按“Figma 字体名 → 字体文件 + 来源 + 许可证”登记；稿里有、登记册里没有的字体会列进缺字体清单并停下，不许悄悄用别的字体顶替。这套机制直接满足本条（具体衔接留到流程阶段）。

## 11.4 外语字体要提前声明（✅ 已定 2026-11-13）

用户修正 11.3：简中按设计稿来；**其他语言用什么字体，要在 Gameweb 制作时提前声明**（外语一般没有单独画稿，字体从稿上读不出来）。

现状：
- **开发侧**（locales.css）：英语标题 Bebas Neue、正文 Noto Sans；日语全用 Noto Sans JP；韩语全用 Noto Sans KR；繁中全用 Noto Sans HK；数字在所有语言里都继续用 Bebas Neue。外语字号也按语言单独调过。
- **Gameweb**：已有一张“语言 × 角色”的字体路由表 `skills/yise-web-ui/scripts/lib/translation/font-routing.mjs`（`FONT_SOURCE_ROUTING`），分标题、按钮、正文三类。但它**写死在代码里**，是伊瑟专用的，换游戏就不适用；而且简中正文写成了 FontquanXinYiGuanHeiTi。

已定内容（2026-11-16 同步语言范围）：
- 需要外语时，在制作前提供**外语字体声明表**：本次实际需要的外语 × 角色（标题、正文、数字，必要时加按钮）；不要求填写未制作的语言。简中字体仍按设计稿，只有简中时无需补其他语言声明；
- 表里的每个字体都必须在字体登记册里有文件、来源和许可证；缺了就停；
- 简中那一行不用填，直接取设计稿；
- 开发侧这页的组合可以作为伊瑟项目的默认表；
- 声明表放在哪、由谁填、Gameweb 怎么读，留到流程阶段（F17）。
