### 9.2 补充：选中背景不一样时（✅ 已定 2026-11-12）

**开发侧现状**：
- “共用一张选中背景”是**按组**共用的：赛区 TAB 一组用 `region-tab-active.png`，决赛 TAB 一组用 `finals-tab-active.png`，两组各自一张；
- 同一组里形状不一样的部分（决赛 TAB 两端的折角 `finals-tab-edge-left/right.png`），开发侧拆成**固定装饰**单独放，不跟着选中背景滑动；
- 开发侧这页没有遇到“同一组里每个 TAB 的选中样子都不同”的情况。

**建议规则（机器按图片比对判断，不靠猜）**：
- 同一组 TAB 的“选中”变体，导出后**像素完全相同**（校验值一样）→ 共用一张选中背景，滑动 0.32 秒加回弹（照开发侧）；
- **不相同**（例如第一个是左尖角，中间是直角，最后一个是右尖角）→ 每个 TAB 用自己的选中图，点击时直接切换，不做滑动；
- 只是两端多出折角这类固定装饰，设计师拆成单独的 `img/`，就仍然可以共用滑动背景（照开发侧的拆法）。

导航（9.1）同样适用这条判断。

- 初步区分：
  - **同款卡片轮播**：内容条数由接口或设计稿决定，按每页几张自动分页（`list/` 加 9.4 规则）；

#### 9.4c 两种轮播的命名和判断（✅ 已定 2026-11-12）

**圆点可以用 `ind/`**，但数量不由设计稿决定：
- 同款卡片轮播的页数 = 卡片条数 ÷ 每页张数（向上取整），条数会变，圆点数量也跟着变；
- 设计稿只需要把 `ind/` 做成组件集，带 `highlight` / `normal` 两个变体（现行规范已有，v2.17），稿上画几颗都可以；
- 网页按实际页数自动生成圆点。开发侧的选手轮播就是这样，圆点由脚本按页数生成（`renderPlayerList` 里的 `dotsFragment`）。

**两种轮播都用 `switch/` 包，机器按 `switch/` 里装的是什么来判断，不另加标记：**

| `switch/` 里装的是 | 判定为 | 页数从哪来 |
|---|---|---|
| 一个 `list/`（里面是重复项，通常带接口列表标记） | 同款卡片轮播，自动分页 | 卡片条数 ÷ 每页张数（每页张数 = 设计稿一页画了几张） |
| 几个各自命名的页面模块 | 不同内容轮播 | 设计稿画了几页就是几页 |
| 两种都有，或者都没有 | 停下上报 | — |

示意：
```
switch/player 选手轮播
├── list/player 选手列表        ← 「列表：player_list」
│   └── card/player 选手卡 ×4   ← 设计稿一页画 4 张，所以每页 4 张
├── ind/轮播点                  ← 组件集 highlight / normal
├── btn/上一页、btn/下一页
```
箭头怎么命名、怎么和 `switch/` 绑定，并入 F1。
