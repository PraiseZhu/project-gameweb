## 首次开场的具体节奏

资源等待结束并到达可绘制帧后，首次入场时间线从 0 开始：

- 0ms：背景开始 600ms 渐显。
- 320ms：顶栏开始进入；手机底栏同时进入。
- 440ms：顶栏晶体开始进入。
- 480ms：社媒开始进入。
- 600ms：slogan 开始 650ms 滑入。
- 700ms：slogan 内部开始 200ms 闪烁。
- 约 1300ms：首次入场阶段结束，满足第 6 项条件时再尝试播放背景视频。

返回首页时，背景仍渐显，slogan 滑入延迟改为 80ms，闪烁延迟改为 180ms；不重新播放顶栏／社媒的首次入场。1300ms 是开场动画计时，不是资源加载超时（15.3）。

## 什么时候播放、停止或直接显示

- 开发样本的五种语言页面都设置 data-motion=true；其他页面的语言范围按 10.0，不固定五语。这一开关与 motion-ready 状态控制新增的整套内容入场；导航滑块、TAB 等交互动画另有触发逻辑，不把这个开关误称为所有动画的唯一开关。
- 每次实际进入另一屏，会触发该屏内容入场；不反复点击当前屏重播。切 TAB、切轮播、展开页脚等会收束相关在途入场，不让旧状态留在半途。
- 开启系统“减少动画”后，取消主要入场、闪烁、切屏叠化、导航／TAB 滑块、轮播过渡、底栏动画和箭头跳动；背景视频不播放，交互状态仍正常切换。
- 缩放、视口或端别变化时结束正在进行的相关动画并对齐布局，保留当前屏／TAB／轮播状态；导航滑块和弹层连续切换有各自的接续处理。
- 只让当前可见内容参与：隐藏 TAB、轮播页和另一设备的装饰副本不参与当前入场。
- PC 和手机共用主要动效类型，但距离、方向与排布按各端分别写；例如 PC 赛程从中心展开，手机赛程从上方进入。
- 这些效果由开发针对页面模块的 class、CSS 变量、状态和 JS 事件指定，不是从任意 Figma 图层自动推导，也不是给所有 img/ 一律添加动画。

### 每类规则都写清的内容

1. 谁动：作用于模块整体、标题整体还是各个子项；同一对象不能因为同时匹配多类就重复叠加。父子需要分别运动时，组合规则明确各自作用。
2. 怎么动：改变哪些属性、起止位置、方向、距离、时长、速度曲线，以及组内顺序／间隔。最终位置和尺寸仍以清单为准。
3. 何时动：首次进入、再次进入、切 TAB、轮播翻页、开关弹层或数据更新分别规定；同类对象与同种触发组合对应同一规则。
4. 何时不动：重复点击当前项、隐藏内容、系统减少动画等沿用已定约束；是否重播和连续操作如何接续写清。
5. 两端怎么用：电脑和手机共用明确的规则身份；需要不同方向或距离时，在规则中分别声明，不让 agent 临场选择。

## 16.2 内容模块逐项／分批入场间隔（✅ 已定 2026-11-13）

**统一为 60ms（0.06 秒），电脑和手机同值。** 依据当前开发两端 CSS，用户在“统一 60ms 并同步修正 9.3”的建议后回答“可以”。

- 每后一项／批比前一项／批晚开始 60ms。同一批内部共同开始；按该组的起始时间计算，4 项依次为 0、60、120、180ms，组本身的起始延迟另算。

## 16.3 普通分区标题入场参数（✅ 已定 2026-11-13：照开发侧）

用户要求先确定普通分区标题的方向、距离、时长和缓动，并明确“如果开发有，就照着开发的标准走”。已核实开发侧有对应的完整 CSS 规则，因此按现有实现记录，不另选数值。

| 参数 | 已定值 | 说明 |
|---|---|---|
| 入场方向 | 从上方往下滑入 | 起点在最终位置上方，结束回到设计稿对应位置；横向位置不变 |
| 位移距离 | 0.24rem；相对最终位置 y 从 -0.24rem 到 0 | 根字号为 100px 的基准下等于 24px；随第 7 项的页面 rem 适配缩放，不固定成所有视口都移动 24px |
| 持续时间 | 560ms（0.56 秒） | 电脑和手机同值 |
| 缓动 | cubic-bezier(0.16, 1, 0.3, 1) | 先快后慢、平稳停下，不回弹；保留精确曲线，不替换为笼统的 ease-out |

- ews2026/css/styles.css 的 `html.has-motion.motion-ready .page.is-active .section-header` 设置 `--entry-y: -.24rem`，并使用 `entry-reveal 560ms cubic-bezier(.16, 1, .3, 1) both`。
- 同文件的 entry-reveal 关键帧从相对最终位置的偏移和 opacity 0，回到最终位置和 opacity 1。
- ews2026/cn.html 的 section-header 包含标题水印和 h2；mobile.css 的 section-header 规则未覆盖上述动效参数。

### 正文和卡片内部文字

- 正文不逐字、逐行、逐段追加独立入场。赛程说明、选手姓名／赛区、视频标题／简介／日期等，跟所属卡片或模块整体运动。
- 正文自身不另定方向、距离、时长和缓动；这些参数取所属动画单元。所属单元没有独立入场时，正文保持正常排版显示，仍可随整屏切换。
- 卡片内的小标题不套 16.3 的分区大标题动画，避免父卡片动一次、内部文字又叠加一次。
- 普通独立长正文、纯文字列表的专用入场参数，当前开发样本没有提供。本轮不从标题或卡片参数推演一套；新的未覆盖场景仍按 P6 明确后再处理。

依据：开发侧 .text、.player-info、.video-copy、.description 等规则只定义文字与排版；HTML 中这些文字位于 schedule-card、player-card、video-card 等模块内，入场动画加在外层。

### 列表的动画单元与参数

| 类型 | 动画单元 | 方向与距离 | 时长与缓动 | 播放组织 |
|---|---|---|---|---|
| 赛区排行 | 每张 rank-card 整体，包含内部排行行、文字和底图；rank-row 不独立入场 | 从左侧 0.18rem 到原位，同时 opacity 0→1 | 位移 560ms，cubic-bezier(0.22, 0.61, 0.36, 1)；渐显同为 560ms，ease-in-out | 卡片依次错开 60ms，沿用 9.3／16.2；不把 60ms 再加到卡内每行 |
