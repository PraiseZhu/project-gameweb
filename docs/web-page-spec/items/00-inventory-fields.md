## G5 细化：艺术字和纯文字怎么区分（5.1～5.5 已定，2026-11-11）

核查了设计稿（来自线上页 model，PC）：

- **艺术字在稿上本来就不是文字图层。** `img/slogan` 是组件实例，里面没有文字图层（已转曲）；`img/LOGO` 是两张位图。
- **出问题的是另一种情况：设计师把真文字放进了 `img/` 组里。** PC 有 12 处，都是 `img/` 组里夹着文字图层，例如：
  - `img/卡片背景` 里的日期“11/07 - 11/08”、奖金“1000 / 5000 / 30000”；
  - `img/底部固定素材` 里的“ETHRIA”“2026 EWS IT'S MY TURN”；
  - `img/对阵背景` 里的日期；
  - `img/空状态` 里的“COMING SOON”。
- **开发侧对这 12 处的处理**：全部做成网页文字，导图时把文字层排除。例如底栏的品牌和标语用 Alimama ShuHeiTi / Segoe UI Historic 写成 HTML；奖金金额、COMING SOON 都是 HTML。带渐变和发光的赛程卡标题也用 CSS 做成网页文字。

已定规则（5.1～5.5）：

| # | 规则 | 检查方式 | 信息来源 |
|---|---|---|---|
| 5.1 | 除 bg/、kv/ 固定素材外，稿上的**文字图层**做成网页文字，包括 `img/` 组内文字；bg/、kv/ 内文字随固定素材整体导出 | 机器：非 bg/、kv/ 固定素材内的文字须在页面 DOM 里找到对应；bg/、kv/ 各素材按整图验收 | 设计稿；2026-11-19 用户修订 |
| 5.2 | 非 bg/、kv/ 的切图排除可编辑文字，按底图/盖层规则导出；bg/、kv/ 固定整图不排除内部文字 | 机器：区分 bg/、kv/ 整图例外与其它分层切图，保持原遮挡关系 | 设计稿；2026-11-19 用户修订 |
| 5.3 | 稿上**不是文字图层**的（转曲、位图），一律当图片。设计师转曲或出图，本身就等于标注了“这是艺术字” | 机器：按图层类型判断 | 设计稿 |
| 5.4 | 带语言的艺术字（slogan、logo）用 `img/` 组件集的 `lang` 变体，文件名带语言后缀 | 机器：沿用现有规则 | 设计稿 |
| 5.5 | 非 bg/、kv/ 固定素材中的文字效果 CSS 做不出来时（例如复杂纹理字），设计师必须在稿上转曲。机器不做判断，也不擅自截图；bg/、kv/ 内文字不要求先转曲 | 人工：设计侧负责；bg/、kv/ 沿整体导出例外 | 设计稿；2026-11-19 用户修订 |

### 5.6 文字和底图混在一起时，导出哪一层（✅ 已定 2026-11-11）

核查（线上页 model，按绘制顺序和区域重叠计算）：图组里夹文字的，PC 12 组里有 3 组、手机 10 组里有 1 组，**文字上面还压着别的图层**（都是赛程卡、奖金卡这类卡片背景组）。其余组的文字都在最上层。

开发侧的做法：赛程卡拆成三层。最下面是底图 `schedule-card.png`，中间是网页文字，上面是单独导出的角色插画 `schedule-art-*.png`。奖金卡同样分成底板和装饰图两张。

已定规则：

| # | 规则 | 检查方式 | 信息来源 |
|---|---|---|---|
| 5.6a | 文字**下面**的所有非文字图层，合并成一张底图（导出时隐藏文字） | 机器：按图层顺序判断 | 设计稿 |
| 5.6b | 文字**上面且和文字有重叠**的图层，单独导出成一张盖层图，网页里叠在文字上面 | 机器：按图层顺序和区域重叠判断 | 设计稿 |
| 5.6c | 文字上面但**不和文字重叠**的图层，并进底图（视觉上没有区别，少一张图） | 机器 | 设计稿 |
| 5.6d | 文字被当作遮罩，或文字上面压着特殊混合模式（叠加、正片叠底等），网页上无法分层还原。这种情况停下上报，由设计侧改稿，不自行处理 | 机器发现，人处理 | 设计稿 |

### 5.7 底图和盖层图是否带坐标（✅ 已定 2026-11-12）

开发侧（赛程卡为例）：
- 底图 `schedule-card.png` 实际是 736×1070 像素，即 3.68×5.35rem，比卡片本身大一圈，因为外发光也被导出进图里了。所以 CSS 写的是 `left:-.07rem; top:-.095rem`：**相对卡片左上角**，而且是负数。
- 盖层插画 `.art` 用正常排版加负边距 `margin-top:-.145rem` 叠上去。
- 坐标只写在 CSS 里。`manifest.json` 只记了来源节点和宽高，**没有记位置**。

Gameweb：清单里每张切图都有 `sliceExport.box`，但它是**整张画布上的绝对坐标**（手机端例如 x=20274）。不换算就没法直接写进开发侧那种按模块组织的结构。

已定规则：

| # | 规则 | 检查方式 | 信息来源 |
|---|---|---|---|
| 5.7a | 每张切图在清单里都要记录：所属模块、层级（底图或盖层）、**相对所属模块左上角**的 x/y、导出宽高 | 机器：字段齐全检查 | 设计稿（由清单抽取） |
| 5.7b | 图层框和导出框分开记。阴影、外发光让导出图比图层大时，差值就是偏移量，CSS 按偏移量写负坐标 | 机器：像素门对比 | 设计稿 |
| 5.7c | 网页 CSS 里的位置和尺寸，一律由这些数值 ÷ 200 换算成 rem，不能目测 | 机器：抽查 CSS 数值和清单是否一致 | 清单 |
| 5.7d | 【优化】交付包的 `manifest.json` 在开发侧格式基础上，增加 `module`、`layer`、`box` 三个字段，方便追溯和检查 | 机器 | 清单 |

### 5.8 盖层图压着文字，缩放时怎么保证和底图对齐（✅ 已定 2026-11-12，选 B）

**不跑位的基础（开发侧已经做到）**：全页尺寸都用 rem，rem 跟着屏幕宽度（或超宽屏时的高度）一起变。底图、盖层、文字都按同一个比例缩放，所以缩放本身不会让它们错开。

**会跑位的几种情况（开发侧代码里能看到风险）**：

1. **盖层跟着文字排版走。** 赛程卡的角色插画 `.art` 排在文字后面，用负边距往上叠。文字一变高，比如外语标题换行或字号变化，插画就会被往下推。开发侧的补救是在 `locales.css` 里按语言加 `padding-block: calc((.31rem - var(--locale-schedule-size)) * .7)`，硬把文字块的高度凑回原值。每种语言都得手工凑，很脆弱。
2. **卡片高度没锁死。** 赛程卡只写了 `min-height: 5.255rem`，文字多了卡片会被撑高，底图却不会跟着变。
3. **单位混用。** 一个元素用 rem，另一个用 px、百分比或图片原始尺寸，缩放比例就不一致。
4. **断点切换。** 手机端换了另一张图，尺寸、位置必须取手机端清单的数值，不能沿用电脑端。

#### 开发侧怎么保证盖层不被文字推跑（2026-11-12 查证，`styles.css` 1262–1345 行、`locales.css` 90–100 / 227–247 行）

开发侧用的办法是**把文字占的高度锁死**，具体有三招：

1. **标题只占一个字号的高度。** 标题 `font-size:.4rem; line-height:1.5; margin-block:-.25em`，行高多出来的部分被负边距抵掉，标题块正好占 `.4rem`。
2. **日期不许换行。** `.month` 设了 `white-space:nowrap`，`.dates` 设了 `white-space:pre`。文字再长也只会横向溢出，不会变高。
3. **外语字号变小时，用内边距补齐。** `padding-block: calc((.4rem - var(--locale-schedule-size)) / 2)`，标题块总高仍然是 `.4rem`（手机端用 `.31rem` 和 `×.7` 的版本）。各语言字号分别是：英 `.37rem`、日 `.25rem`，手机端为 `.31 / .28 / .17rem`。

效果：文字块总高恒定，插画 `.art` 虽然排在文字后面，位置也不会变。

局限：
- 标题本身**没有设禁止换行**，翻译一长就会折行，插画随即被推下去。
- 每种语言、每个模块都要手工算补偿值，新增语言或改文案都要重算。
- README 没有逐语言测量盖层位置的记录。

历史方案比较（已选 B，A 不采用）：
- **A 照开发侧**：图层跟着文字排。把“文字块高度锁死”写成硬规则：每个文字块固定占位高度，不许换行，或者限定行数；外语按公式补偿；机器在 5 种语言下检查各模块内文字块高度是否一致。
- **B 优化**：图层钉在模块上，不跟文字排（即 5.8a）。不需要补偿公式，坐标直接取自清单。

已定规则：

| # | 规则 | 原样 / 优化 | 检查方式 | 信息来源 |
|---|---|---|---|---|
| 5.8a | 底图和盖层图都以**所属模块**为定位参照，相对模块绝对定位。**不跟文字排版流动**，文字怎么变都推不动图层 | **优化**（开发侧盖层跟随文字流动） | 机器：检查 CSS，图层元素必须是相对模块定位 | 清单 |
| 5.8b | 图层的宽、高、位置全部写 rem，数值来自清单，不用 px、百分比或图片原始尺寸 | 原样 | 机器：CSS 数值抽查 | 清单 |
| 5.8c | 模块的宽高按稿锁定（rem）。文字超长时在模块内换行或截断，不撑大模块 | 原样（开发侧移动选手卡已经这样锁定） | 机器：不同语言下模块尺寸一致 | 清单 |
| 5.8d | 电脑端和手机端分别取各自清单的数值，断点切换时图层位置一起切换 | 原样 | 机器：两端分别校验 | 清单 |

### G4 间距和排列（✅ 原则已定 2026-11-12：会增减的组必须用自动布局；固定组从位置推算；没用就停下上报）

用户追问：a（机器从位置推算）和 b（设计稿用自动布局）有什么区别？模块被取消后，能不能按自动布局让剩下的自动补位、间距不变，而不是空出一块？

**区别在于是否知道“少一个、多一个时怎么排”，而不只是数字从哪来。**
- a：位置只说明“现在这一刻排成什么样”。三张卡等距居中，机器只能**猜**它们是一排、等间距、居中排列。少一张时怎么排，要靠猜。这和“写进规范、不靠 AI 判断”相冲突。
- b：Figma 自动布局本身就写明了方向、间距、对齐（居中还是靠左）、内边距、是否换行，和网页的 flex 布局几乎一一对应。少一个时怎么补位，设计稿已经定好，不需要猜。

**开发侧这页确实需要“少一个时自动补位”，而且它的页面已经做到了，但规则是开发自己定的，不来自设计稿：**
- 决赛赛果、赛事视频两屏由接口开关控制，关掉时导航按钮跟着隐藏，导航用 flex 排列，自动收拢；
- 决赛 TAB：只有一个阶段时，容器宽 4.12rem 居中；两个阶段时宽 7.815rem（`width:max-content` + 居中）；
- 选手卡、新闻卡每页 1～3 张时整体居中，不补空卡；
- 排行榜按实际人数隐藏行，0～3 人时换短卡底图；
- 社媒按钮数量按地区不同（国服 5 个，海外 3～6 个）。

这些在开发侧都写成 flex/grid 的居中或靠左排列，**靠左还是居中，是开发判断或用户指定的**。

**现状未知**：现有清单只抽了约束，没有抽自动布局，所以不知道这份设计稿里哪些组用了自动布局。需要在流程阶段查 Figma 原稿（见 README F5）。

**已定原则：**
- **会增减的组**（导航、TAB、列表、卡片组、社媒、由接口开关控制的模块），设计稿**必须用自动布局**。清单抽取方向、间距、对齐、内边距、换行，网页照着写成 flex。
- **不会增减的固定组**（装饰、底图内部、固定标题），可以不用自动布局。机器从位置推算间距（a）。
- 会增减的组没用自动布局时，机器停下上报，由设计改稿，不猜。
- “哪些组会增减”，由 G2 的重复项标记，以及接口开关的配置来确定，不靠判断。

#### 哪些内容会增减：来源约束与流程参考（2026-11-12）

不靠看图判断，只认三个**外部事实来源**：

| 来源 | 什么算“会增减” | 本页例子（开发侧） |
|---|---|---|
| ① 接口数据约定 | 内容条数由接口列表决定的组；由接口布尔开关控制显隐的模块，以及对应的导航项 | `player_list`、`news_list`（模板生成）；`regional_qualifier` 每组最多 6 行；`is_jssg_visible`、`is_news_visible` 控制两屏和导航按钮 |
| ② 地区或语言配置 | 不同语言或地区下，数量不同的组 | 社媒按钮（国服 5 个，海外 3～6 个，海外没有微信） |
| ③ 设计稿命名标记 | 设计师在命名里明确标为“重复项”（G2 已定）或“可选模块”的组 | 待命名规范补充（F1、F2） |

后续流程的检查参考（不在本轮实现）：
- 三个来源里任何一个命中，就算“会增减”，这个组必须用自动布局。
- 三个来源都没命中，就算“固定”，按位置推算。
- 机器检查：接口约定里的每个列表字段、每个开关字段，都必须在设计稿里找到对应的命名组；找不到就停下上报。

需要的前提：接口数据约定要有一份成文的字段表。开发侧 README 里写了字段说明，但不是正式的约定文件（见 dev-requests R8）。
