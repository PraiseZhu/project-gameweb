# B2-Font：三级自动找字与公共字体库

归属 #157，追踪总目标 #151。前置 #164（B2 输入补齐）与 #166（B3 交接包）已完成并合入最新 main（B3 merge 3895a5a034311dd47081fa94c15fb5e7f968ace7）。

## 问题

当前 B2 能识别字体缺失并要求补充，但没有公共字体库、本机候选扫描和确认后的可复用登记。设计师每次重复提供同一商用字体；系统字体、非商用字体和网页不可用容器也可能被误当成可复用资源。字体是 B2 的前置阻断项，不能拖到多语言制作阶段才首次发现。

## 方案

- 在仓库根目录旁的项目运行目录 fonts-library/ 建立不入 git 的公共字体库。目录固定包含 files/、registry.json、licenses/ 和 .scan-cache.json；字体原文件使用 <slug>-<weightOrVF>-<sha8>.<ext> 命名，必须按内容 SHA-256 防止覆盖历史版本，入库只能原子真拷贝，禁止符号链接。
- Level 1 优先读取公共库：每次仍真实读取文件、重算 SHA-256、解析内部身份/字重/轴/容器，并按当前页面真实字符覆盖核验。只有唯一有效真实身份、已确认商用许可、文件摘要未漂移、字重/轴匹配且字形覆盖通过时，才零询问复用；入库记录不能替代文件和字形核验。
- Level 2 仅在公共库无法满足时扫描候选目录。macOS 扫描 ~/Library/Fonts/（包括 EagleApp 等子目录）和 /Library/Fonts/，Windows 扫描默认字体目录，并支持调用方注入自定义目录。单测通过目录注入隔离，不能依赖宿主机真实字体目录。跳过网页不可用的 .ttc 等格式，复用现有真实解析链读取 name、OS/2、fvar、cmap 等元数据；以路径、大小、mtime 建立 .scan-cache.json，缓存失效后必须重新读取文件。
- 扫描候选必须按真实 SHA-256 去重，并重新执行真实身份、字重/轴和当前字符覆盖校验。系统字体以及许可文本含“非商用”“商用需授权”“Noncommercial”等风险线索的候选显示红色风险警告，绝不静默复用。单页所有候选合并为一张确认卡；同家族多字重需求优先可覆盖的 VF，同等合格静态字体默认 .ttf 优先于 .otf。未确认或拒绝的候选不得入库、不得打包、不得改变 B2 放行结果。
- 用户确认合规后，无论候选来自本机扫描还是设计师手工提供，都立即把真实原文件和许可说明原子真拷贝到公共库并登记 registry.json；确认时间、来源、真实解析身份、字重/轴、容器、SHA-256 与许可状态必须可追溯。再次运行应命中 Level 1，不能重复询问。
- Level 3 只有公共库和本机扫描均无法满足时触发：准确报告家族、字重/轴、使用位置、覆盖语言和缺失字符，要求设计师补原文件或改稿替换；禁止自动联网下载、近似字体替代或静默使用系统字。
- 与现有 B2/B3 兼容：从公共库复用的字体必须继续作为完整真实原字体和许可进入 B3 b:handoff，并在隔离迁移后通过 handoff:check；遵守 H19/H20，只加载实际使用字体。

## 验收条件

1. Level 1：预置唯一合法商用字体库条目时零询问复用；每次复核文件字节、SHA-256、真实身份/字重/轴与当前字符覆盖；摘要漂移、重复身份、许可失效、缺字和坏库条目均 fail-closed。复用资源进入 B3 后，整包迁移并断绝原 B 目录、原字体目录访问，handoff:check 仍通过。
2. Level 2：单测注入 macOS/Windows/自定义目录，覆盖 EagleApp 子目录、缓存命中与失效、跳过 .ttc、SHA 去重、VF 优先、静态 .ttf > .otf、内部元数据优先于文件名和真实字符覆盖。候选按页合并为一张确认卡，确认前不写库，确认后原子真拷贝、许可落盘和 registry 登记完成，第二次运行命中 Level 1。
3. 风险与缺件：系统字、非商用/需授权字体和许可未知候选必须红标并阻断静默复用；拒绝/未确认候选不写库；库内文件被篡改、软链替代、坏字体表、缺字、路径逃逸或登记与实际文件不一致均拒绝。Level 3 报告必须精确到家族、字重/轴、位置、语言和缺失字符，不能联网或近似替代。
4. B2 流程兼容：保留已有 fonts-b2.mjs、font-inspect.mjs、font-identity.mjs、font-unpack.mjs、cmap.mjs 的真实解析和边界；只对新增/变化项补问，不重复询问已确认答案；显式坏 shape/null、许可待确认和多端/多语映射仍按既有合同阻断，不得用自动找字洗白。
5. 回归门：黄金合成样本覆盖单/双端、单/多语、中文与目标外语、完整/缺字、真实 TTF/OTF/WOFF/WOFF2、正常/空/缺值/多字重/状态映射和许可边界；旧获准 EWS 真稿只作为真实访问与负例回归，记录读取版本与缓存重放，不能冒充新真稿放行。one-page、figma-naming、release:audit、diff-check 全部无回退。
6. 必须先完成独立异构代码复审并取得 APPROVED，再由另一模型在隔离副本完成独立验收并取得 PASS；正式审核/验收/测试产物绑定同一候选和 base。范围内缺陷最多允许两轮受控自修；两轮后仍不收敛、业务歧义、需要新依赖或门禁异常立即停止并留档。
7. 通过双审后只提交授权文件，绝不提交 fonts-library/、_tmp/ 或敏感信息；正常执行 pre-push 钩子，创建关联 Draft PR，接入自动跟进，CI 全绿后自动转 Ready。Ready 不等于合并，也不等于 #151 全新干净真稿终验。

## 不做

不修改或运行时导入 skills/yise-web-ui、skills/torchlight-web、skills/ews-web；不新增第三方依赖；不自动联网下载字体；不把未经确认的本机字体写入库或交付；不导图、不做 HTML/C/C1-C4 页面实现、不写回 Figma/飞书；不启动 B4、C1 或其它后续切片；不自动合并 PR；全新干净真稿 A→H 终验归 #151。

## 已确认决定

本切片紧接已合入 B3，在最新 main 上使用独立工作树实现；公共库是运行时目录并加入根 .gitignore，不进入 git。现有真实字体解析工具继续复用，新增逻辑只负责库、扫描、缓存、候选合并确认和入库登记。执行边界止于 PR Ready 且 CI 全绿；用户明确授权全自动创建任务、派发开发/复审/验收 Worker、最多两轮受控返修、提交推送和 Draft→Ready，禁止合并。
