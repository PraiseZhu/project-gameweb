# C 模块：单语言完整页面制作方案

日期：2026-11-20。状态：完整讨论稿，待用户整体确认。确认只收口C方案；继续后续流程讨论，不启动实施、代码改动、审核派工或真实页面制作。

## 问题

C把通过B的交接包制作成一份可独立打开、代码符合开发侧标准的单语言完整页面，交D进行第一次完整验收。需要明确谁负责什么、按什么依据制作、什么时候算可送验，以及以后成品改稿如何处理。不能用方案确认或通用测试代替实际产物通过。

## 已确认决定

- A～H及两轮完整制作/验收顺序沿[讨论记录](task_plan.md)R023/R046；[B完整方案](b-input-handoff-plan.md)已由R181确认，原确认快照保持不变。
- C从一开始制作可交付目录形态的真实页面文件，QA独立在外，验收围绕同版产物（R183）。
- 脚本处理明确的素材/字体/换算/压缩工作；AI按明确输入组织代码、优先复用合格实现；程序核对实际结果（R185）。
- 按屏和功能模块组织，同类逻辑复用而各实例状态独立；双端共享逻辑身份/数据/状态，展示差异分别保留（R186/R187）。
- 同一设计对象改中文用途名仍可对应原代码；不要求人维护中英对照表或逐项审批翻译。删建/复制/功能变化须核对（R189/R190）。
- 下载/社媒等正式外链由开发填写，设计侧做好能力与集中配置入口（R194）。
- 动画相关代码必须符合开发侧标准；效果参数后续可调，不用历史数值表锁死当前送验（R196/R197）。
- 已完成且代码合格的页面以后调整设计，点对点修改，只检查改动及实际影响，不重跑完整流程（R192）。

完整成品要求引用[最终交付与验收标准](delivery-and-acceptance.md)，尤其适用2026-11-20动画修订。本方案不新增视觉参数、页面功能、库或工具选型。

## 方案

### 1. C 接收什么、完成什么

输入是B已通过、与本次范围和稿件版本对应的交接包，包含设计事实、实际资源来源、字体/数据/状态/动效说明和必要的测试材料。按本次项目明确的基础语言制作；不擅自指定固定语言，也不扩成未约定的语言集合。项目尚未明确基础语言时只补该项信息，不重问整个A范围。

C完成该语言在实际约定端别上的页面：静态内容、布局适配、页内交互、数据读取/缺省能力、动画代码以及素材处理/压缩。双端必须一起完成，单端不补另一端。多语言扩展属于E；D是第一次完整验收，C完成不代表D通过或H已冻结交付。

### 2. 制作分工

| 工作 | 负责方式 | 不得越过的边界 |
|---|---|---|
| 读取交接包、导出素材、核对/整理字体、单位换算、压缩和来源记录 | 脚本执行明确规则，优先复用既有能力 | 不按画面估尺寸，不改字体、编码政策或素材边界；不能完成则报告 |
| 页面结构、模块样式、交互/数据/动效代码组织 | AI按B输入和成品规范组合合格实现，必要时补代码 | 不重新设计、不猜功能、不补稿外模块；实际输入不明回来源补清 |
| 产物内容、引用、规范与基本运行检查 | 程序核对当前产物，不能机械判断的部分做源码核对 | 不靠AI口头自批，不用文档/假目录单测代替真实页面 |

这里明确职责，不决定具体脚本名称、函数、文件修改列表或检测实现；这些留到整体方案确认后的实施设计。

### 3. 页面结构和代码组织

按页面、屏、功能模块及条目组织，嵌套取B明确的关系；全页共用固定块只在实际需要的位置共用，不逐屏重复，不套稿上没有的空壳。模块整体有清楚的代码归属，不要求每个图层成为组件，也不强制每模块一文件。

成品使用原生HTML/CSS/JS；主体、标题、正文直接存在HTML，不能运行时重建整页。不引入页面框架、第三方库或成品构建依赖。可变列表可沿已定template方式生成条目，不能以此替代静态主体。

样式按既定文件分工：共用/电脑基准、手机差异、按需外语覆盖；分段注释、变量管理，不散落静态逐节点行内样式。class管样式、data-*管业务、is-*及相应ARIA属性管状态；页面逻辑按既定main.js原生组织，开发配置集中。遵守既定字体、正文、外部文字及外链处理约束。

PC/手机同一模块保留统一的逻辑身份、数据和应保持的状态，各端尺寸、布局和素材各取对应稿；结构能共用时共用，确有差异时保留必要展示分支。两端展示不得出现重复DOM ID、隐藏端仍可交互或重复触发行为。跨端按已确认规则保持当前内容而非强保页码；菜单/弹层按既定规则关闭。

同类轮播/菜单等可共用处理代码，不同实例各自维护状态，避免一个轮播带动另一个。复用不覆盖各对象已有行为差异，也不授权接管开发正式公共组件。

### 4. 设计对象怎样对应代码

B已确定的模块身份、来源对象和动作目标关系进入C；C生成有含义的代码名称及唯一对象引用。按钮找目标依据已解析的关系，不在浏览器里按中文文字、翻译结果、图层顺序或样式class碰运气。

英文代码名称由制作环节整理并检查、复用已明确对应；设计师不另维护中英表，也不用手抄节点ID。同一对象仅改名称或文字、尺寸，仍对应原代码并识别变化。删除重建、复制成新对象、改变功能或来源发生歧义时核对具体关系，不冒认旧对象。名称引用冲突仍须解决，不能以“保留身份”为由继续使用错误接线。

来源追溯保存在制作记录及适用素材manifest中，交付DOM不依赖Figma调试标记；已有固定公共接入口的ID不得擅改。具体英文映射和ID生成算法留实施阶段，不改变这些要求。

### 5. 素材、字体、数据和交互

- 素材沿B明确计划取实际源：bg/kv按已定整图例外处理，其他live文字按标准做网页文字；各层位置、遮挡、导出框与偏移有依据。不能正确分离的情况报告，不擅自截图代替。C完成压缩及资源追溯，保留标准要求的原始/历史文件；不为体积过线裁字体或删素材。
- 字体使用本次已声明且核验的完整文件、真实字重及来源/许可；只加载当前语言实际使用的字体，缺必需资源不能用别的字体冒充。
- 数据按B字段约定读取、填充、显示状态；未填地址不请求，失败按已定静态缺省。用独立测试材料检查适用分支，不把样例当正式名单/内容，也不将测试数据放入产品目录。
- 页内切屏、TAB、轮播、菜单/弹窗等实际功能要完成并可操作；缺目标或关系冲突不能写空函数冒充完成。
- 下载/社媒等外部跳转做好外观、配置字段和读取/跳转能力。开发后续填真实地址即可接入，无需重改按钮代码；真实下载成功/第三方可达性不作设计侧送验前置。空地址不误跳、不填假网址，未规定的缺省表现不自行统一改成提示/隐藏/置灰。
- 正式接口、语言网址、公司组件等仍由开发后续接入，C按已有标准预留接入口和正确缺省，不自造替代服务。

### 6. 动画代码必须合规，效果参数后续可调

动画相关代码遵守原生实现、CSS/JS文件归属、模块组织、class/data-*/is-*分工、main.js结构及变量管理；不强制只能CSS或只能JS。静态行内样式禁令不误伤合法运行时动画更新。动画不能破坏按钮目标、焦点、显隐和正常页面操作。

实现代码不合规，或必要检查未执行，不能送验。时长、位移、方向、曲线、延迟、播放节奏等效果参数后续可调，不拿历史参数表锁死当前送验；效果待调与代码违规分开记录。不据此自行改变设计或取消正常功能要求。

### 7. C 交 D 的八项判定条件

这八项是汇总后的完整待确认送验方案，已纳入外链和动画修订；不是某个页面已通过的报告。

| 项 | 可交D的条件 | 证据范围 |
|---|---|---|
| 1 内容齐全 | 本次语言、端别、屏、模块、文字、图和必要状态齐全，无漏做/未明制作信息；允许标准已定义的缺省/待公布 | 对照B输入的实际产物清单 |
| 2 独立可运行 | 普通静态服务可打开，无缺失本地资源和代码运行错误；无JS时规定的静态主体仍可见 | 实际页面启动、资源、错误和无JS检查 |
| 3 代码合规 | 原生实现、结构/样式/脚本/配置组织、命名、状态与ID引用符合开发侧标准 | 当前源码程序检查及必要源码核对 |
| 4 基准画面/适配已做 | 实际各端按对应基准打开检查，无已知错图/缺字/错字体/遮挡错误；双端做1024/1025往返初检 | 实页基准记录/字体加载/跨端结果；完整视口与还原度验收在D |
| 5 交互与动画代码可验 | 页内功能接完且基本操作跑通；动画代码合规、效果后续可调；外部跳转有可配置入口 | 接线对账、实际基本操作及代码结果；正式链接可为空，不验真实外站服务 |
| 6 数据和缺省可用 | 本次所需字段/开关/列表已实现；正常、未配置/失败、空列表/单页/多页等适用基本分支可测 | 当前页面使用明确隔离样例的结果，不冒充正式数据 |
| 7 资源/压缩完成 | 字体/素材齐全，格式/压缩/来源/引用和manifest一致，体积及超限按既定政策记录处理 | 实际文件、尺寸、格式、资源摘要和体积记录；不新增阈值 |
| 8 送验版本一致 | D拿到的就是自检对应版本，来源、设计对照、自检和测试材料可定位；QA与测试材料不混进产品目录 | 版本/文件摘要及证据引用；未执行的D专项验收如实标待验 |

本次适用项全部pass且无已知未修问题，才可标“C完成，可交D”。缺必要实现/输入或必需自检未运行不能通过；n_a只用于实际范围不含该功能，不能掩盖漏做。正式外链待填、外部服务未接通及效果参数待调不等同于制作缺失。

### 8. C 输出及与 D 的边界

C输出一份单语言完整页面目录，以及放在目录外的送验说明/证据引用：对应哪版B输入、哪些语言/端/模块已制作、做过什么自检、哪些项目仍待D验收。测试材料与设计对照一并可定位，不要求重复填写已有事实。

满足上述条件后沿固定链路交D，不能把“可送验”说成“验收通过”，也不提前进入多语言扩展或冻结交付。D按既定先机器白盒、后人工黑盒进行第一次完整验收；完整视口/视觉/画质和实际交互验收的执行方法在D方案继续确定。动画以代码合规及正常功能为门槛，不能把旧效果参数验收重新带回来。

已有当前同版、与D标准匹配的证据可核验复用，不因阶段名称不同重复同一检查；没有执行过的D项目不能伪记pass。C不能把明显未完成工作留给D代做，D也不以正式上线工作作为设计侧通过前置。

### 9. 失败回改和成品后续修改

首次制作：缺设计/字段/关系等输入，定位到具体来源补清；已有正确输入但代码实现错误，由C修改。不能通过篡改清单或降低规范掩盖问题。修改后更新受影响的产物和证据，保留未执行/失败原因，不以旧版本通过替代新结果。

已制作完成且代码符合标准的页面后续改稿，遵守用户明确的点对点方式：只读取变化及实际关联信息，沿模块对应修改相应代码，检查改动处及实际受影响部分。未变的代码/配置保留，不重抽完整清单、不重生成整页、不重跑完整A～H；共用代码发生变化时才扩大到真实使用处。必要的来源记录维护不变成完整B前置。

局部修改中若目标含义变化、身份不清或现有人工修改发生冲突，只核对具体问题；不擅自覆盖，不自动删文件，也不增加每次都要另建完整候选包的要求。

## 验收条件

未来实施C时须证明：

1. 实际输入可形成上述单语言完整产物，设计/代码对应及资源来源可追溯。
2. 八项送验条件能检查当前真实产物；缺项、代码违规和未运行不误放行。
3. 外链真实值由开发后填、动画效果可调的边界不被错误阻断；其入口/代码实现仍须合规。
4. 当前版本的产物和证据一致，能交D继续完整验收，不混淆送验、验收通过与正式上线。
5. 成品点对点改稿能保留未变内容，只验证真实影响范围，不恢复全流程重跑。

上述是未来验证目标，当前没有实施或运行这些检查。文档测试通过仅证明文档一致性。

不重新讨论已定页面规范，不把外链/上线工作转给设计侧，不锁死动画效果参数，不把成品改稿变成整链制作。
