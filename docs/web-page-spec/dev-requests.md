# 现在需要开发提供什么

2026-11-17 更正：**只要 Gameweb 制作前会用到的资料。** 设计交付完成后，开发接入、管理和上线要用的东西，不放进这份清单。

本文件用于发给开发的短清单。接手人需要了解每项的用途、拿到后怎么用、已有与缺失情况，请读三份交接文件中的 [第 3 份：开发制作资料交付说明与核对要求](developer-handoff.md) 第 1～4 节；包括逐项用途、使用方式和资料完整性要求。本文件只用于发送短消息，不单独作为接收验收依据。

1. **Onepage 制作 Skill**
   开发制作 ews2026 时使用的 site-components/skills/onepage-template/ 完整目录，包括 SKILL.md 和实际引用的配套文件，并标明版本。

2. **页面制作要复用的模板、动效和资源**
   尤其是已用于页面的闪烁动效样式及说明；如复用样本字体，补缺失的来源／许可。ews2026 工程我们已有，确认使用版本、补缺的文件即可，不用重复传，也不要求整个组件库。

3. **页面数据格式说明和 JSON 样例**
   告诉 Gameweb 字段叫什么、是什么类型、哪些是列表／开关、语言如何区分；有现成字段命名规范一起提供。用于生成页面读取和显示数据的代码。若页面字段的安排受后台能力限制，只说明这种限制，不要后台入口、账号、权限或操作手册。

4. **现有的制作和验收方法／要求**
   用什么工具从 Figma 取数、导图，怎样检查还原度；如果已有图片／字体、视频／包体积、浏览器／性能要求，一起提供。给现成文件或简短说明即可，没有就说明没有，不用另写一套规范。

核心区别：我们需要知道“Gameweb 怎么把页面做对”，不需要现在收集“开发拿到页面后怎么上线”。

本清单已同步 [开发交接表](developer-handoff.md) 和 [Gameweb 流程待讨论事项](gameweb-workflow-discussion.md)。原 R1～R16 的历史与本次范围更正保存在 [核对记录](coverage-audit.md)，不作为另一份索取清单。HTML v1 要求未改，本轮未向开发发送请求。
