# A～H 各环节负责的功能

更新日期：2026-11-20。已确认（R222 职责清单，R223 解耦机制，R224 检查移到 C）。机制细节见 [decoupling-mechanism.md](decoupling-mechanism.md)。

| 环节 | 负责 | 不负责 |
|---|---|---|
| A 确认范围 | 收 Figma 页面链接、语言集合、基础语言、端别；用户确认后出范围记录；链接无效、不是规范稿、范围冲突时停 | 不问模块、字段、交互等页面内容 |
| B 整理输入 | 读稿上确定的事实；只补稿上定不了的：外语字体、组件状态和动作、数据字段、动效、译文和外语素材；检查后出交接包；改稿时只出变化交接包；缺件语言单独标出，补齐后只为该语言补一版；记录开发要填的配置项 | 不导出素材、不做页面 |
| C 制作单语言页面 | 按交接包导素材、做画面、适配、交互、数据缺省、动画代码、压缩；跑全套自动检查（含像素门）并自己修到全部通过；按设计师意见修改并复跑受影响检查；按变化交接包点对点改稿；记录预留入口和未填外链 | 不读交接包以外的需求；稿件版本对不上就停，退回 B |
| D 第一次验收 | 核对 C 的检查记录：检查项齐全、对应这一版页面、用的是当前规则，对不上退回 C；再交设计师在 QA 页面看，意见交 C 修；设计师满意后出设计确认版 | 不重跑检查、不改页面 |
| E 制作多语言页面 | 以设计确认版为基准，按交接包里的语言部分做其他语言，每种一份独立 HTML；跑全套语言检查并自己修完；按设计师意见修改；缺件语言暂停 | 不改基础语言已确认的设计；不自行翻译 |
| F 第二次验收 | 核对 E 的检查记录，对不上退回 E；整组交设计师看，意见交 E 修；满意后出设计确认版（与 D 同一种格式） | 不重跑检查、不改页面 |
| G 最终包核对 | 只读设计确认版；按开发标准打包；在包上重新核对文件、引用、字体、编码、manifest、画面和交互 | 不压缩、不改效果；有问题退回 C 或 E |
| H 冻结交接 | 冻结版本；汇总文件清单、校验值、全程检查记录和开发待办（来自 B、C 的记录）；交给开发 | 不负责正式上线 |

共用工具（不算环节）：Figma 读取和导出、自动检查、像素比较、QA 页面。各环节调用后把结果写进自己的记录。

每个环节交出：成果 + 统一格式的环节记录（读的哪版输入、交出哪版成果、是否通过、问题清单、问题退回哪里、开发待办）。C↔设计师、E↔设计师的修改循环，以及 C、E 内部的自动修复，同一问题连续两轮没修好或一轮下来问题数没减少就停下报告。
