# 第 5 项：样式文件怎么组织（CSS）

状态：✅ 已定（2026-11-12）

## 开发侧现状（实测 ews2026/css）

| 文件 | 行数 | 用途 |
|---|---|---|
| `styles.css` | 2878 | 电脑端基准，加上所有共用样式 |
| `mobile.css` | 1456 | 只在 ≤1024px 时生效，覆盖手机端差异 |
| `locales.css` | 301 | 四种外语的字体和字号覆盖（按 `html:lang()`） |
| `flicker-entrance.css` | 11 | 从公司组件库原样拷来的闪烁动效 |
| `site-footer.css` | 39 | 从公司组件库原样拷来的统一页脚 |

其他实测数据：
- 尺寸几乎全用 rem（styles 450 处、mobile 492 处）；px 只有 33 处，主要是断点（1024/1025px）、页脚组件和 1px 细线；
- 颜色**大多直接写色值**（79 处），只有 3 个颜色变量 `--ews-white`、`--ews-gold`、`--ews-purple`；
- 层级 `z-index` 共 63 处，取值随手定（-1、0、1、2、3、4、5、10、30、40、50、60、100、110），没有统一的层级表；
- `!important` 4 处。

## Gameweb 现状

一个 `runtime/ews.css`（约 15KB）负责通用外壳。每个节点的位置、尺寸、字体都写在 HTML 的行内样式里，没有按模块分的样式。

## 5.1 样式文件怎么分（✅ 已定 2026-11-12）

已定规则（按开发侧）：
| # | 规则 | 原样 / 优化 | 检查方式 |
|---|---|---|---|
| 5.1a | 电脑端基准和共用样式放 `styles.css`；手机端差异放 `mobile.css`；实际需要的外语字体字号放 `locales.css`；公司组件接入后其样式原样保留、单独成文件，接入归开发（6.4），不要求 Gameweb 随包附带组件 | 原样组织，组件分工按后续修订 | 机器：核对适用文件及职责范围 |
| 5.1b | 不允许行内样式（`style="..."`），样式全部写在样式文件里 | 原样（开发侧 README 写明“无静态内联样式”） | 机器：扫描 HTML |
| 5.1c | `styles.css` 内按“全局 → 页面骨架 → 各屏（按屏顺序）→ 各模块”分段，每段有注释标题 | 优化（开发侧大体如此，但没有成文） | 人工 |

## 5.2 颜色、字体、时长统一成变量（✅ 已定 2026-11-12，含颜色全部变量化）

**开发侧：**
- 颜色变量只有 3 个：`--ews-white`、`--ews-gold`、`--ews-purple`。其余 79 处颜色直接写色值，例如 `#d36bee` 出现 7 次、`#ab70ff` 出现 5 次、`#b56dff` 出现 3 次；
- 字体做了变量：`--ews-font`、`--ews-display-font`，外语靠覆盖这两个变量切换；
- 动效时长做了变量：`--page-transition-duration`（400ms）、`--entry-hold`、`--intro-duration`、`--active-transition-duration`。

**已定规则：**

| # | 规则 | 原样 / 优化 | 检查方式 | 信息来源 |
|---|---|---|---|---|
| 5.2a | 字体、动效时长统一写成变量，放在 `styles.css` 开头 | 原样 | 机器 | 固定模板 |
| 5.2b | **颜色也统一成变量**：设计稿里用到的每种颜色在开头定义一次，正文只引用变量，不直接写色值 | **优化**（开发侧只做了 3 个） | 机器：正文里不允许出现裸色值 | 清单（设计稿颜色） |
| 5.2c | 外语、手机端只改变量值，不重复写整段样式 | 原样（`locales.css` 就是这么做的） | 人工 | — |

## 5.3 尺寸用什么单位（✅ 已定 2026-11-12）

**开发侧实测**：所有尺寸、位置、字号、间距都用 rem（约 990 处）。px 只出现在三个地方：
1. 断点判断：`@media (max-width: 1024px)`、`(min-width: 1025px)`、`(max-width: 750px)`；
2. 公司统一页脚的手机端补丁：`padding: 12px / 24px / 30px`（styles.css:310–326）。页脚组件本身用 px，开发侧不改它；
3. 系统安全区的兜底值：`env(safe-area-inset-bottom, 0px)`。

注释里写明了换算：PC 稿 3840 宽 → 页面 1920 基准 → `1rem = 100px`；手机稿 750 宽 → 375 基准 → `1rem = 100px`。

**已定规则：**

| # | 规则 | 原样 / 优化 | 检查方式 | 信息来源 |
|---|---|---|---|---|
| 5.3a | 页面上的尺寸、位置、字号、间距一律用 rem，数值 = 设计稿数值 ÷ 200 | 原样 | 机器：扫描样式文件，除白名单外不允许出现 px、vw、% 尺寸 | 清单 |
| 5.3b | px 只允许三种情况：断点判断；公司组件的样式及其补丁；系统值的兜底（如安全区 `0px`） | 原样 | 机器：白名单 | 固定模板 |

## 5.4 谁压在谁上面（层级 z-index）（✅ 已定 2026-11-12，以修订版 5.4a′～c′ 和下方“弹层”补充为准）

**开发侧实测（页面级，大的压在上面）：**

| 层级值 | 是什么 |
|---|---|
| 110 | 手机语言弹层 |
| 100 | 手机菜单、提示条 `.site-status` |
| 60 | 前景装饰层 `.foreground-layer`（不挡点击） |
| 50 | 顶部导航 `.site-header` |
| 40 | 社媒侧栏 `.social-shell` |
| 30 | 底栏 `.footer-strip` |
| 10 | PC 语言下拉 |
| 1 / 0 / -1 | 屏幕内容、背景 |

模块内部只用 0～5，例如卡片底图 0、文字 1、选中的 TAB 3、装饰 4、分页点 5。

问题：数值是写的时候随手定的，没有一张总表；新加一个东西时不知道该用多少。

**历史草案（已被下方 5.4a′～c′ 与弹层补充取代）：**

| # | 规则 | 原样 / 优化 | 检查方式 | 信息来源 |
|---|---|---|---|---|
| 5.4a | **页面级层级固定成一张表**，写成变量放在 `styles.css` 开头，例如 `--z-bg`、`--z-screen`、`--z-fix`、`--z-foreground`、`--z-overlay`、`--z-toast`。各块只引用变量，不写数字 | 优化（开发侧的顺序照搬，只是整理成表） | 机器：正文不出现裸数字的页面级 z-index | 固定模板 |
| 5.4b | 几个 `fix/` 固定块之间谁在上，按设计稿图层面板的上下顺序，在 `--z-fix` 段内依次排 | 原样（开发侧顺序与稿一致） | 机器 | 设计稿 |
| 5.4c | 模块内部只用 0～9，按设计稿图层顺序：底图在下，文字在中，盖层在上（与 5.6 一致） | 原样 | 机器 | 设计稿 |

### 用户追问：直接按设计稿图层顺序不行吗（2026-11-12 核对设计稿）

**可以，而且应该以设计稿为主。** 设计稿里每屏的图层顺序是清楚的。以 PC 第 2 屏为例，从下到上：

`bg/sec2`（背景）→ `fix/底部固定背景`（底栏）→ `img/前景素材`（前景）→ 奖金、赛程卡等内容 → `标题模块` → `fix/顶部导航通栏`（导航）→ `社媒`

**新发现**：开发侧有一处没照稿。稿上前景装饰在内容**下面**，开发侧把前景层放到了最上面（60，比导航的 50 还高，只是不挡点击）。按“以设计稿为主”，以后照稿来。两种做法看起来有没有差别，放到校准时实测（README C3）。

**设计稿决定不了的，只有稿上没画的东西**：手机菜单、语言弹层、提示条、公司统一页脚、PC 语言下拉的展开状态。这些需要一张固定表，而且永远压在所有设计稿图层上面。

**修订后的已定规则（结合下方弹层补充）：**

| # | 规则 | 检查方式 | 信息来源 |
|---|---|---|---|
| 5.4a′ | 稿上画了的东西，层级**全部按设计稿图层顺序**，包括页面级的固定块、前景、内容，以及模块内部 | 机器：网页层级顺序和清单里的图层顺序一致 | 设计稿 |
| 5.4b′ | 稿上没画的东西（菜单、弹层、提示条、统一页脚等）用一张固定的层级表，写成变量，永远在设计稿图层之上 | 机器 | 固定模板 |
| 5.4c′ | 正文不写裸数字，统一引用变量或按顺序生成 | 机器 | — |

### 已定补充：弹层一律在最上层（用户 2026-11-12）

- 弹出类的东西本身就永远在页面最上层：点击后出现，关闭后消失。包括 `modal/` 弹窗、`dropmenu/` 展开后的菜单、手机导航菜单、语言弹层、提示条。即使它们在设计稿里画在别处，也不按稿上的位置排层级。
- 同一时间只开一个弹层，打开新的会先关掉旧的（开发侧现状：菜单和语言层互斥）。
- 所以固定层级表实际只剩“弹层”这一档。

## 5.5 `!important`（强制覆盖）什么时候能用（✅ 已定 2026-11-12，原样采纳开发侧）

**开发侧实测，共 4 处：**
1. `[hidden] { display: none !important; }`：凡是标了“隐藏”的，一定隐藏，任何样式都不能把它顶出来；
2. `.no-js [data-lazy-picture] { display: none !important; }`：浏览器关掉脚本时，隐藏等待懒加载的空图片；
3. 统一页脚容器 `overflow: hidden !important;`：压住公司页脚组件自带的滚动设置；
4. `.is-overlay-closing * { pointer-events: none !important; }`：弹层淡出的过程中，里面的东西不能再被点到。

规律：全是“强制隐藏或强制不可点”，以及“压住外来组件”，没有一处用来修普通样式。

**已定规则：**

| # | 规则 | 原样 / 优化 | 检查方式 |
|---|---|---|---|
| 5.5a | `!important` 只允许用于两类：① 强制隐藏、强制不可点（隐藏属性、无脚本兜底、弹层关闭中）；② 覆盖公司组件自带的样式 | 原样 | 机器：白名单，其余出现就报错 |
| 5.5b | 普通样式冲突靠写清楚选择器解决，不许用 `!important` 硬压 | 原样 | 机器 |
