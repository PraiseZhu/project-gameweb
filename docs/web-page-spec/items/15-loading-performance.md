# 第 15 项：加载、性能指标、异常表现

状态：✅ v1 成品要求已定稿（2026-11-16）；普通静态图失败处理由开发按具体项目处理；实际验证与校准归 Gameweb 流程，不影响定稿。

## 已在别处定过的

- 位图最终交付 WebP，视频暂定 MP4 + H.264、无音轨、faststart；体积上限是设计侧暂定建议，见第 13 项。
- 字体使用 `font-display: swap`，先显示系统字，再替换为设计字体；按语言加载当前页需要的字体，见第 11 项。
- 背景视频只留接入口；只在首屏、电脑端、未开启减少动画且入场动画结束后播放；组件不存在就跳过，见第 6 项。
- 开启减少动画时不播背景视频，见 6.8。
- 禁用 JS 时静态内容仍可见，不要求切屏或读取后台数据，见 6.3；不重复确认这项要求。

## 开发侧现状（ews2026）

- 首屏 PC 和手机背景分别用 `link rel="preload"` + `media` 预加载；实际页面用 `picture` 选择当前端的 `kv-pc.jpg` / `kv-mobile.jpg`。
- 其他屏的图片用 `data-src` / `data-srcset` + `data-lazy-picture`，切到对应屏时才加载。
- 懒加载图片后面保留 `<noscript>` 副本，用于禁用 JS 时显示静态图片；这是开发侧落实 6.3 的做法。
- KV 视频由背景视频组件延后挂载，不在手机端或减少动画模式播放；视频就绪后再隐藏静态 slogan。

来源：本机 ews2026 的 cn.html 预加载声明与 main.js 图片地址激活、syncHeroVideo 逻辑，以及提交 39f9d71 的 README“图片懒加载（2026-11-04）”。首屏 slogan、导航等保留正常加载；预加载背景不等于首屏只准请求一张图。

## 15.1 首屏和非首屏怎么加载（✅ 已定 2026-11-13：按开发侧定）

已定，沿用开发侧：

1. 页面首次打开只预加载当前语言、当前端的首屏静态背景；不同时下载电脑和手机两张，也不预加载其他屏的图片。
2. 非首屏图片保留懒加载标记，切换到对应屏时按需请求；不能打开页面就把全部屏的图片一次性下载。
3. 首屏视频不参加首屏预加载，按第 6 项的接入口和播放条件延后挂载；静态背景和 slogan 先作为可见内容。
4. 首屏 slogan、导航和其他当前可见内容正常加载；页面所需 CSS、JS、当前语言字体及已定的接口请求不受“只预加载首屏背景”限制。
5. 手机端、减少动画模式初次打开页面时不请求背景视频文件；视频组件尚未接入时按第 6 项跳过，不阻塞静态页面。
6. 禁用 JS 时的静态内容展示沿用 6.3，不要求交互与后台数据加载。

| # | 规则 | 原样 / 优化 | 检查方式 | 信息来源 |
|---|---|---|---|---|
| 15.1 | 当前语言和当前端只预加载首屏静态背景；其他屏按需懒加载；视频延后挂载 | 原样，沿用开发侧 | 浏览器冷启动网络记录：背景预加载只命中当前端；未进入的后续屏图片不提前请求；切入后按需请求；手机/减少动画初次打开时不请求背景视频文件；首屏其他内容正常显示 | 开发侧 HTML、JS 与用户确认 |

本轮只确认并记录规范，没有修改加载实现，也没有执行浏览器网络或弱网实测。

## 15.2 图片、背景视频加载失败时怎么显示（已有回退已定；普通静态图不由本规范规定）

### 开发侧已核实的处理

- 动态头像：地址没有提供或加载失败时，显示页面自带默认头像；不拿示例人物冒充真实头像。main.js 的头像 error 回调只执行一次，并隐藏相关头像装饰。
- 新闻／视频封面：地址缺省或加载失败时，回到卡片模板已有的默认封面；失败回调只执行一次。此类封面的规则已在 9.8 确认，本条只引用。
- 背景视频：组件报告 error 或非 AbortError 的自动播放失败时，移除 is-ready；CSS 隐藏视频层，恢复已有静态背景和 slogan。保留现有页面，不显示额外错误弹窗。
- 首屏背景图和 slogan：加载失败事件、解码失败会结束对应入场等待；但没有发现给这些图片换备用图的统一处理。普通静态图、Logo、装饰图也未发现统一的隐藏破图或替代图片规则，不能声称开发侧已经处理妥当。

依据：本机 ews2026 的 js/main.js（videoCoverFallback、setImageSource、syncHeroVideo、waitForIntroImage、头像与封面 error 回调）及 css/styles.css（hero-video、is-ready 与 slogan 的显示规则）。本轮为代码核对，未做浏览器故障模拟。

边界：

- 本条讨论访客打开页面时发生的加载失败，不是允许缺图交付。制作／验收时发现资源缺失，仍按 13.2 报错，不得凭回退画面判定完整还原。
- 默认图片和静态背景必须使用已经提供并确认的素材；没有默认图时不能让 agent 临时画一张或拿示例图替代。
- 背景视频组件仍由开发接入，Gameweb 按第 6 项保留接入口和衔接逻辑，不因此自行实现替代播放器。
- 这里的失败指已经收到加载／解码错误或播放拒绝；请求长时间无响应的处理按 15.3：不另设超时和自动重试。外链视频的播放由目标网站负责（9.8）。
- 15.2a、15.2b 按开发侧确认；15.2c 明确排除出本规范，设计侧不补规则，具体情况交开发处理。没有修改实现，也没有做浏览器异常实测。

## 15.3 资源等待超时与重试（✅ 已定 2026-11-13：按开发侧现状）

**按照开发制作的 ews2026 页面标准为准：页面不额外设置资源加载超时或自动重试，只保留开发侧已有的失败回退。设计侧不另加等待秒数、重试次数、重试间隔或超时后的新提示。**

本条确认的是沿用当前开发页面的实现，不代表开发侧另有统一的超时／重试规范。具体行为：

1. 图片等待加载成功或失败；首屏背景和 slogan 的入场准备等待当前图片加载／解码完成或失败，没有额外等待上限。失败时按 15.2 已有规则处理，不新增备用图或重复请求原地址。
2. 背景视频没有额外加载超时或失败后定时重试；收到加载错误或自动播放失败后，按 15.2 恢复静态背景和 slogan。
3. 赛事数据接口在页面初始化时请求一次，不设置请求超时、自动重试或定时轮询。404 进入 unpublished，其他请求或解析错误进入 unavailable；页面内容回退沿用 6.5b 和已定的数据规则。
4. 请求一直没有结束时，不由页面在指定秒数后主动中止、宣告失败或重新发请求；维持开发侧现有等待行为。这是当前采用的行为，不新增“保证几秒内恢复”的承诺。

| # | 规则 | 原样 / 优化 | 检查方式 | 信息来源 |
|---|---|---|---|---|
| 15.3 | 不设页面层的资源加载超时和自动重试，只保留开发侧已有失败回退 | 原样，沿用开发制作的页面标准 | 源码核对无额外加载截止计时器、超时取消或自动重试循环；浏览器模拟加载失败检查已有回退，模拟请求挂起确认没有页面自设的中止与重试 | 用户 2026-11-13 明确确认 + ews2026 当前实现 |

范围与依据：

- 本条只约束交付页面的资源加载逻辑，不修改浏览器或网络自身的超时机制，不禁止用户刷新后的正常新请求，也不删除动画、提示条消失等无关计时器；制作工具和验收工具自己的执行超时不属于本条。
- 失败后换到已有默认图属于 15.2 的回退，不等于重试失败地址；视频在页面生命周期或播放条件变化时按现有逻辑调用 play，不等于新增定时重试机制。
- ews2026 的 main.js 中，waitForIntroImage 等待 load／error 和 decode；loadTournamentData 使用无超时取消、无重试循环的 fetch；背景视频组件通过 error／autoplayfail 通知页面执行既有回退。
- README 所记“慢加载超过 1500ms”“数据延迟 1200ms”是测试场景，不是超时参数；不得据此给页面新增超时阈值。
- 15.2c 普通静态图失败显示不属于设计规范范围；本轮仅更新边界，未修改实现、未执行网络挂起或失败模拟。

## 15.4 加载秒数和性能评分（✅ 已定 2026-11-13：暂不另设性能数字）

开发侧现状：当前 ews2026 样本和提交版 README 没有给出“首屏必须几秒内出现”、Lighthouse 分数或 LCP／CLS／INP 等性能指标的合格线，也没有这些性能指标对应的统一测试设备与网络条件。已有记录主要是源码、本地引用、浏览器布局和交互检查；慢网模拟不是性能数值标准。不能据此断言开发团队没有其他内部标准，具体资料列入 R15 待要。

已定：**按开发制作的页面标准继续做，设计侧暂不另设加载秒数或性能评分门槛。已有的首屏优先、按需加载、失败回退和第 13 项暂定体积上限继续执行；未来拿到开发侧明确的性能标准后，再据其确定数值和测量条件。**
