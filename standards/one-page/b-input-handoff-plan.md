# B 模块：输入整理、检查与交接方案

日期：2026-11-20。状态：各项决定汇总后的完整讨论稿，待用户整体确认。确认只收口B方案并进入C讨论，不启动工具开发、审核派工或页面制作。

## 问题

B要把A已确认的设计稿和制作范围，整理成做页可以直接使用的一份完整交接包。不能只有尺寸/文字却缺少字体、数据、状态或动效说明，也不能让做页环节再猜设计意图。

## 已确认决定

- 以[最终页面标准](delivery-and-acceptance.md)为结果要求；独立建设不依赖取得开发内部Skill，但不能猜页面必需输入。
- A只确认来源、实际语言和端别；B负责设计事实与制作说明一并抽取、一起版本化。复用现有出清单能力，不另建第二份手工设计真源。
- 19个前缀及四类通用绑定规则已有局部确认；旧稿/旧游戏链保留兼容。既有本地代码仍停在自测记录阶段，不能当成本方案已实现的证据。
- 字体由工具读取/汇总，设计负责人只确认实际外语字体及无法明确的用途；工具检查资源，统一保存交接（R173）。
- 组件状态从稿上明确关系读取，只问不明确的具体问题；答案随同一份交接包交做页（R175）。
- 跨端保留当前内容，目标页码按各端实际分页确定，来回切换不漂移（R172）。
- 数据字段由B汇总说明，对照已有开发约定，只补未知；明确测试样例用于验证，不混入产品包；没有正式接口可按已确认前端约定制作，不宣称后台接通（R179）。
- 当前已授权制作流程内，B当前版本全部检查通过就自动交C，不增加每次人工点击确认；D/F实际页面验收保留（R177）。

原话与讨论依据见[决策记录](task_plan.md)的R023/R034/R036/R046/R049/R120～R123/R165～R179。只适用于实际需求的规则才检查，不因通用能力清单要求每个页面都具备所有模块。

## 方案

### 1. 先确认读的是正确版本的稿

接收A已确认的page、语言集合、端别和范围版本。页面必须可访问，目标设计集合明确，属于已规范命名来源。链接失效、缺权限、非规范稿、选择歧义、A确认后稿件变化或范围变化，按A既定停止边界处理；不取第一个候选、不缩范围、不沿旧范围合同继续制作。

### 2. 从稿里读取确定的事实

复用现有抽取能力，读取节点、层级、顺序、几何、文字及混合文本样式、各端素材和来源。保留每条事实的来源，不让人重填坐标、图层ID或另一份清单。

- 固定排布取已有设计数据；会增减或隐藏后收拢的列表、导航、TAB等必须有Auto Layout或明确等价的排布依据，包含实际需要的方向、间距、内边距、对齐、换行/尺寸行为。缺信息报告，不凭静态位置发明动态规则。
- 固定槽位与可增减列表分清；唯一模板、条目归属和已有数据声明共同使用，不因同母版就认定后台会增减。
- bg/kv按已定例外整体导出含内部文字；其他live文字保留为网页文字，记录底图/文字/盖层及真实遮挡。不能保持遮罩或混合效果时报告，不擅自截图代替。
- 两端模块沿已定sec范围与唯一名称规则配对；各端几何、素材和结构分别保留。单端范围不强求另一端，双端未匹配也不能自动当作单端专属。
- 产品会用到的默认隐藏弹窗、未选状态仍属于制作内容；ref参考说明不能代替产品状态，未知不能擅自当装饰。

### 3. 只补稿里无法确定的制作说明

| 内容 | 工具先做什么 | 需要补充时问什么 |
|---|---|---|
| 字体 | 读简中字体/字重和文字用途，复用明确声明，核对实际字体资源 | 本次外语各用途用什么字体；有无明确例外；缺哪个文件/字重/来源说明 |
| 状态与动作 | 读能唯一解释的组件变体、实例属性、原型和已定绑定 | 哪个标签属于哪些内容；点击后去哪；两端状态如何对应 |
| 数据 | 汇总字段路径、用途、类型、语言和已有缺省规则，核对正式说明 | 某字段含义/类型/缺值行为不明或冲突；需要保持的内容怎样识别 |
| 动效 | 读取已定规则引用、对象、触发及各端明确适用范围 | 应有动效却缺选择、目标或已覆盖的组合依据 |

已明确的事实不重复问；有冲突不能按读取顺序选一个。补充结果保存到项目统一配置，与设计事实对应，不手改生成清单。设计负责人无需抄节点ID或手填JSON。

字段名有正式约定就原样保留；没有开发资料时以已确认设计字段形成前端约定。工具按已确认规则组织测试样例，覆盖当前功能适用的正常、空/缺值、单页/多页、语言缺项和状态；样例标明测试用途。正式接口地址和业务真实性不作为设计侧已完成声明。

项目中某标签具体点击落点、某组件属性的用途、动态数据的内容身份和内容消失后的处理，必须有明确项目输入或适用的既定规则。未确定就列缺项，不预设统一回第一页、记住上次或夹页；这类项目值不要求在通用B方案里穷举。

### 4. 编成同一份可追溯交接包

包内须包含四组信息；下面是内容分组，不锁工程字段名：

1. 本次做哪些语言、端和屏，以及所依据的范围/稿件/规范版本。
2. 设计稿的实际内容：节点、几何、文字、排布、层级、各端对应、素材来源与切图计划。
3. 已确认的制作说明：字体与资源索引、数据说明/绑定及验证材料引用、组件状态与动作关系、动效引用和必要例外。
4. 检查结果：查了什么、依据哪一版输入、是否通过、剩余问题和影响范围。

字体文件等必要资源必须能从交接记录定位并核验；图片在B只记录来源和导出计划，不承担实际切图。资源版本须可追溯，不能让做页拿到过期引用。测试材料与QA资料可供制作/验收使用，但不进入H最终产品目录。

### 5. 检查通过才放行

B检查当前范围内的来源资格、命名、设计事实完整性、重复/排布依据、跨端对应、字段类型、字体资源、动作/状态目标、动效引用和版本一致性。未运行的检查不算通过。

影响当前交付的缺失、冲突或未知必须阻断，说明“哪块、什么问题、影响什么、该改哪里”；不影响范围的参考/排除项也保留依据。不能为过关静默缩范围或改用旧契约。

稿件有错回稿件；缺声明补声明；工具漏读/解析错则回工具修复，不让正确设计迁就错误实现。改输入后重新出包并复验相关关系及整包版本一致性，旧结果不能直接覆盖新输入。

### 6. 全通过自动交给做页

未来已授权的制作流程中，输入完整、必要声明已确认、当前版本B检查全通过，就自动交C。核对结果可查看，不额外增加“每次点通过”。做页以这份包消费明确结果；发现输入缺口退回B补原来源和重出包，不在生成页里凭猜测补齐。

## 验收条件

这是未来实施B时必须证明的条件，目前未声称已通过：

- 范围或来源版本不符能阻断，不误取稿件、端别或语言。
- 设计事实与制作声明同包可追溯，字体、数据、状态、排布、素材和动效各自有明确来源。
- 缺必要字体/状态/字段/排布、重复目标或来源冲突的反例不能放行；默认隐藏产品内容不能漏掉。
- 同一份输入输出结果一致；改来源后旧包/旧检查不能继续被当作当前版本。
- 全部条件满足能自动交C，有问题则准确定位和回改，不额外要求重复人工确认。
- B通过只证明输入可交接；页面结构、规格、代码和逻辑是否符合开发侧标准，仍由C/E实现、D/F真实页面验收证明，不能用词表或文档测试替代。
