# B3：生成可独立核验的 one-page 交接包

归属 #157，追踪总目标 #151。前置 #164 已完成（PR #165）。

## 问题

B2 通过后，C 仍缺少一份能独立核对版本、制作资料和资源的交接包。B1 或 B2 单独通过，不代表可以开工做页。

## 方案

- 只消费同一运行下当前有效的 A、B1、B2 通过链；核对范围、端别、语言、稿件及配置、译文、字体摘要。不回退更早的通过版，不重新抽取或改写上游，不混入后来修改的配置。复用现有编译、单清单打包、双端配对及环节记录。
- `b:handoff` 生成 `runs/<run>/b3.rN/`：`manifest.json`（`onepage-b-handoff/v1`、范围和版本、能力、文件大小与 SHA-256）；`production/`（最终各端清单、配对、选定译文、制作配置、数据合同、素材来源与导出计划、节点 `visualFingerprint` 和 `blackbox-guide.json`）；`resources/fonts/`（范围内实际使用的完整原字体及来源、许可）；`validation/`（`testData: true` 的同版本 QA 样例）；`evidence/`（来源、版本、定位与待办）；`README.md`。节点指纹覆盖 `imageRef`、`fills`、`strokes`、`effects`、`vectorPaths`、`children`。
- 包内制作引用全部为相对路径；原始 Figma 快照和飞书整表留 B，包只留追溯摘要。缺译和已确定外链的待填网址按原口径保留为带定位的非阻断待办，其余必需项缺失仍拦截。验证资料只供测试和同版本 QA，严禁进入成品。
- 构建前后复核输入指纹，验完实际目录才原子发布并写 `b-handoff` 通过记录；保留既有版本。`handoff:check` 必须使用调用方传入的 `--expect-version`、`--scope-version`、`--consumer-contract` 校验，不能用包内自报信息代替。错误报告标出位置、影响和责任环节。

## 验收条件

1. 黄金样本实测单端、双端、单语、多语；完整和缺失译文、待填外链、全范围真实字体和许可、数据合同及隔离样例均按预期处理。验证正常、缺值、空列表、分页、缺当前语言等实际适用场景，不用样例数量代替覆盖。
2. 把整包迁到隔离目录，断开 B 运行目录和原字体目录，实际运行 `handoff:check` 仍通过。缺文件、改字节、坏引用、路径逃逸、未知契约、缺能力、错范围或错版本均拒绝。
3. 当前 A/B1/B2 缺失、损坏、错版或 B2 未通过时不产出可用包；输入中途变化、中断或并发不得覆盖旧包或形成假通过。同一输入重跑内容版本稳定。旧获准 EWS 真稿验证真实访问及缺件拦截，不要求其放行；缓存重放与真实联网证据分开记录。
4. `one-page`、`figma-naming`、`release:audit`、`diff-check` 无回退；独立复审通过后再独立隔离验收，最终 CI 全绿并转 Ready。发现范围内缺陷最多自修两轮，不收敛或门禁异常即停。Ready 不等于合并或新真稿终验。

## 不做

不导图、不做 HTML 或 C 消费实现、不写回 Figma/飞书、不新增依赖、不修改或运行时导入旧游戏 skill。不启动 B2-Font、B4、C1 或其它后续切片，不自动合并。全新干净真稿 A→H 终验归 #151。

## 未决项

无待定业务规则。本正文须确认后发布；同一范围不重新讨论已定案事项。

## 已确认决定

仅打包当前已通过的 B2 版本，字体随包复制，原始快照留 B，产品资料与验证资料分离；按两级验收口径推进。执行边界为 B3 的交接包与收包校验，止于 CI 全绿且 PR Ready。
