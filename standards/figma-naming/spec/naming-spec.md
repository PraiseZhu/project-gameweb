# 设计稿命名规范

> 版本 **v2.14**（2026-08-27）。本文件是本项目判定命名对错的**唯一事实来源**。
> 同目录 `spec.mjs` 是它的机器可读镜像，`tool/test/spec-drift.test.mjs` 锁住两者一致（前缀表、参数表、前缀语法参数、§4.2 两道排除闸门、§6 规则清单、§7 名字形态、版本号）。
> 规则的 `why` / `fix` 文案属于实现侧解释，在 `src/rules.mjs` 里维护，不在本文件锁定范围内。
> 判定后果所依赖的下游假定见 [`consumer-assumptions.md`](consumer-assumptions.md)。

---

## §0 总原则

**只有前端接入时机器要消费的层才需要前缀**——切图、交互、分区、行为。纯容器、纯编组保持原名即可，不必全稿每层都改。

前缀覆盖率低本身不是问题。**问题是「该被消费的层没有声明」和「声明了但机器认不出」。**

判断一个元素要不要前缀，问：前端拿到这份稿，需要知道它是什么才能正确接入吗？

- 需要切成图片资源 → 视觉类前缀
- 需要能点、能滑、能切换 → 交互/复合类前缀
- 需要按屏拆分或固定定位 → 结构类前缀
- 都不需要 → 不用前缀

## §1 前缀总表

格式：`前缀/名称[@参数]`

### 结构类

| 前缀 | 含义 | 约束 |
|---|---|---|
| `sec/` | 屏幕分区 | 在体检根子树内搜集；无识别前缀的纯布局 `frame` / `group` 透明；名称须以编号开头，如 `sec/1-首屏` |
| `fix/` | 视口固定悬浮层（侧边导航、返回顶部） | 不参与分区流；可选 `@from=N`：滚到分区 N 及以下才出现 |
| `ref/` | 说明性参考稿（滚动示意、状态说明） | **整个子树忽略**：不检查、不报警 |

### 视觉类（命名即切图意图）

| 前缀 | 含义 | 参数 |
|---|---|---|
| `img/` | 静态装饰图、美术字标题 | 语言切图走组件集变体属性 `lang`，不挂 `@` 参数 |
| `bg/` | 大面积底图 | — |
| `kv/` | KV 视差分层（背景/角色/前景各一层） | `@parallax=0–1` |

这三类**不需要另加 Export 标记**。Export 标记只在需要非默认格式或倍率时才加，是可选覆盖；命名才是资产身份的来源（假定 A1）。

### 交互类

| 前缀 | 含义 | 参数 |
|---|---|---|
| `btn/` | 可点击元素 | `@link=` 跳转 / `@go=` 状态转移 / `@sec=N` 滚到分区（**均为选填**） |
| `hot/` | 透明热区 | `@link=` / `@go=` |
| `modal/` | 弹窗帧 | 应是独立 frame，不叠画在页面稿内 |

`btn/` 的动作参数是选填。点击后发生什么由下游配置决定，不属于命名规范的职责（假定 A3）。

### 复合与行为类

| 前缀 | 含义 | 参数 |
|---|---|---|
| `dyn/` | 运行时动态组件（倒计时、进度、今日标记） | 子树免前缀语法与图像未命名报警 |
| `mix/` | 图文混排大块（日历网格、活动列表） | 只命名容器，子树免前缀语法；带图像填充的叶子由清单自动拆成 `img/` 切图 |
| `scroll/` | 可滑动区 | `@x` 横滑（默认）/ `@y` 纵滑 |
| `switch/` | 切换器 / 轮播容器 | — |
| `tab/` | 切换器的页签条 | — |
| `ind/` | 轮播进度指示（圆点） | 按最近 `sec/` 祖先（无则体检根）在作用域内寻找 `switch/`；组件集每个变体根由清单带切图，零件不命名 |

`scroll/` 的第一个子层视为内容轨道，轨道的直接子项为列表 item。**轨道内的图仍需命名**——它们是要切的资源（假定 A5）。`scroll/` 写在 `mix/` 里面时，滑动裁切身份不变：视口仍是 `scroll/`，不因为外层是 `mix/` 就整块切图或丢掉轨道。

`mix/` 只命名容器，设计师不必给内部零件加前缀（子树仍免前缀语法与图像未命名报警）。**清单自动拆切图**：`mix/` 子树里带图像填充、且没有自己前缀的叶子升为 `determined` `img/`，带 `sliceExport`；无前缀 TEXT 仍是可改文案。这不是让做页去猜 `skipped` 子层（假定 A8）。

`ind/` 全组同名是允许的，序号按同级顺序推定，不需逐个改名。它的作用域是最近的 `sec/` 祖先（没有 `sec/` 祖先时用体检根）；作用域内恰好一个 `switch/` 时，即使两者是兄弟或隔着纯布局容器，也能唯一确定联动对象。作用域内没有候选时报 `N-IND-NO-CAROUSEL`，有多个候选且 `ind/` 不在任一 `switch/` 内时报 `N-IND-CAROUSEL-AMBIGUOUS`；若祖先链已有 `switch/` 则由嵌套关系短路确定（假定 A4）。页上用到的 `ind/` 组件集，每个变体根由清单写 `sliceExport`（假定 A8）；内部小钻石不命名、不单独切图。

**`img/` 语言切图（假定 A8）：** 只有同时满足三条才跟页面语言换图——组件集前缀是 `img/`、变体属性名是 `lang`（大小写不敏感）、且至少有两个不同的精确小写 `cn` / `tw` / `en` / `jp` / `kr`。组件集叫功能名（如 `img/模块2可替换素材`）；变体层保持 Figma 自动名 `lang=cn`，不要改成 `img/标题-cn`。稿上只做小写五码：`cn` 与 `CN` 是两个变体，`tc` / `zh-CN` / `ja-JP` 都不是合法值。没有 `lang` 轴、只有一个变体、普通 `img/`、`CN` / `xx`、以及 `Property 1=cn` 这种旧写法，都不跟语言，始终画稿上选中的那一张。不要写 `@lang`——参数表没收它，声明会被静默丢掉。多轴组件集只认名为 `lang` 的那一轴。未画的语言（例如只有 `cn`/`tw`）不做出清单失败条件；缺的语言由做页切过去时 fail-visible，不回落默认中文图。页上语言 key 仍是 `zh-CN` / `zh-TW` / `en` / `ja` / `ko`；`region=cn` 是国服，不是语言。映射：`zh-CN→cn`、`zh-TW→tw`、`en→en`、`ja→jp`、`ko→kr`。页上用到的这类组件集，只有精确小写合法变体根由清单写 `sliceExport`；零件不命名。

`sec/` 不要求是体检根的直接子层。下游在体检根子树内搜集所有 `sec/`；中间无识别前缀的纯布局容器透明。若 `sec/` 分散在多个逻辑父层、嵌在另一个 `sec/` 内，或祖先链上已有带语义前缀的节点，分别按 §6 的 `N-SEC-SCATTERED` / `N-SEC-NESTED` 判定。

## §2 @参数表

| 参数 | 可挂前缀 | 取值 | 作用 |
|---|---|---|---|
| `@link=<key>` | `btn/` `hot/` | 任意字符串 | 跳转语义；URL 在配置里，不写死在稿里 |
| `@go=<state>` | `btn/` `hot/` | 任意字符串 | 开弹窗时抄弹窗图层名，如 `@go=modal/顶部导航`。不要写图层 id |
| `@sec=<N>` | `btn/` | 正整数 | 滚动跳转到分区 N |
| `@from=<N>` | `fix/` | 正整数 | 滚到分区 N 及以下才出现，并钉视口。不写则进页就钉 |
| `@parallax=<0-1>` | `kv/` | 0–1 的数 | 视差系数 |
| `@x` / `@y` | `scroll/` | 纯标记 | 滑动方向 |

## §3 文字纪律

**TEXT 节点默认不需要任何前缀。** 节点类型本身已经说明它是文字，再加前缀声明一次是重复劳动。无前缀的 TEXT 是**可改文案**——下游按文字内容还原，改字即可换文案。

**但名字压过类型：** TEXT 一旦挂了视觉类前缀（`img/` `bg/` `kv/`），就按**切图**消费，不再当作可替换文案（假定 A6）。`img/标题字` 是美术字切图，文字内容只是图形的一部分；前缀声明的是这个节点的资产身份（假定 A1），不是文字语义。

**本规范不收 `txt/`。** 前缀与节点类型重复：TEXT 的类型本身已声明它是文字，`txt/` 在 v2.0 已删除（见 §8）。要表达「这层是文字」不需要任何前缀；要表达「这层是切出来的字」用 `img/`。

**本规范不规定文案 key 如何生成**——那是下游的事（假定 A6）。本规范只要求两件：

1. **A6 前半句（文案不得烙进栅格资产）目前无规则检测。** 原检测手段 `N-TEXT-IN-SLICE` 于 v2.6 退役，因为它把「切图节点内有 TEXT」当作「文案被烙图」的代理，而按前缀定义这个代理在结构正确的稿子里恒为假。候选替代规则「切图节点内部含非视觉类前缀」真稿命中 0，无证据不加。
2. **文案的尺寸约束照抄稿内设置。** 紧凑控件（`btn/`、`tab/`、`switch/`、`ind/` 祖先链内）的固定尺寸会被还原成定宽定高；长段落则按定宽自动换行还原，独立段落不因固定尺寸本身报警。

## §4 前缀的形态与边界

### §4.1 什么算「在用前缀」

前缀的**约定写法**是小写 + 半角斜杠，但判定「这个图层是不是在试图用前缀」时按**宽容**处理：

- **大小写不敏感**：`IMG/` `Sec/` 与 `img/` `sec/` 同义，不算写错；
- **半角斜杠两侧允许空格**：`img / 装饰` 与 `img/装饰` 同义，不算写错；
- **全角斜杠 `／` 与半角 `/` 同义**，不算写错（假定 A0）；
- **反斜杠 `\` 仍算写错**，报 `N-PREFIX-SLASH`——消费侧按 `/` 或 `／` 识别，反斜杠匹配不上；
- **总表外的词**不管大小写、空格与否，仍按 `N-PREFIX-NOT-IN-TABLE` 报（§4.3）。

判定参数（机器镜像见同目录 `spec.mjs` 的 `PREFIX_SYNTAX`）：

<!-- PREFIX_SYNTAX -->
| 参数 | 值 | 含义 |
|---|---|---|
| `minWordLen` | 2 | 斜杠前的英文词至少 2 个字母才考虑判定；单字母一律放过 |
| `separators` | `/` `／` `\` | 这三种分隔符都算「试图用前缀」 |
| `shortWordMaxLen` | 4 | 词长 ≤ 该值时按短词处理 |
| `typoThresholdShort` | 1 | 短词与总表项的编辑距离 ≤ 该值才判定为拼错并给建议 |
| `typoThresholdLong` | 2 | 长词的同上阈值 |

斜杠前含数字、空格断开的名字（`04/10`、`Frame 12/copy`）不匹配上述形态，天然放过。**非 ASCII 的词（如 `按钮/确定`）目前不判定**——无法区分「中文前缀」与「名字里本来就有斜杠」。

### §4.2 排除：什么不算在用前缀

以下是 Figma 自动生成的图层类型名。它们出现在斜杠前时**不算**在用前缀，否则 `Group/2` 这类名字会被判成自造前缀。

<!-- NON_PREFIX_WORDS -->
`group` `frame` `rectangle` `ellipse` `vector` `line` `star` `polygon` `union` `subtract` `intersect` `exclude` `mask` `component` `instance` `slice` `arrow` `boolean`

这张词表是针对已知自动类型名的防误报闸门。**扩表要克制**：扩太宽会重新放过自造前缀，而自造前缀是静默失效——比误报危险。出现真实误报再补词，不预先扩表。

词表只能枚举已知的 Figma 自动名称，覆盖不了任意英文文案。因此再加一道结构性排除闸门：

<!-- STRUCTURAL_NON_PREFIX -->
| id | 判据 | 为什么 |
|---|---|---|
| `text-name-equals-characters` | `type === "TEXT"` 且图层名去空白后等于自身文字内容去空白后 | Figma 默认取文字内容当 TEXT 图层名。文案里带斜杠（`part / one`、`5 / 10`）会让自动名看起来像在用前缀，而设计师从未声明过任何东西。词表是枚举，覆盖不了任意文案，只能用结构判据 |

这道结构性排除**只作用于前缀语法判定**：`N-PREFIX-NOT-IN-TABLE`、`N-PREFIX-SLASH` 在命中该判据时不报。它不改变其它规则的适用范围；例如 `N-TEXT-FIXED-SIZE` 仍照常判定。

### §4.3 总表外的前缀词一律报错

不在 §1 总表内的 `词/` 视为错误——机器不认识它，声明的意图会被静默忽略，设计师以为标了、实际等于没标（假定 A0）。

两条出路：改成总表内的前缀，或去掉斜杠前的英文词（说明这层本就不需要被消费）。确实需要新语义的，走规范升版流程加进总表。

## §5 结构与导出纪律

Export 勾选是 Figma 里的人工导出设置，不是资产身份契约。前端只按 `img/` `bg/` `kv/` 等命名前缀识别资产；本工具不把 Export 勾选作为切图意图或结构错误的判定依据。

其它约定：

- Export 可继续用于人工导出预览或覆盖格式/倍率，但不会替代资产命名
- `kv/` 的用途是视差分层。同一父层下只有一个 `kv/` 时视差无从体现，用 `img/` 表达更准确

## §6 规则清单

21 条错误码的**元信息在本表锁定**（错误码集合、级别、处置、依据性质）。每条的 `why`（不改会怎样）与 `fix`（怎么改）是实现侧解释，在 `src/rules.mjs` 里维护，不在本表内。

**处置**按「有没有可接受的出路」定义：

| 处置 | 含义 |
|---|---|
| `must_fix` | 唯一正确的出路是改命名或去掉标记，没有「保持现状也对」这一路 |
| `must_answer` | 存在显式的接受路径（如确属美术字），但必须给出答案，不能忽略 |
| `confirm` | 不改也不一定错，只需核实 |

**依据性质**：`deterministic` = 由语法或结构矛盾直接判定；`heuristic` = 由经验规则推断意图。**`heuristic` 的规则不允许是 `must_fix`**（测试强制）。

<!-- RULES_TABLE -->
| 错误码 | 级别 | 处置 | 依据性质 | 假定 |
|---|---|---|---|---|
| `N-PREFIX-SLASH` | P1 | must_fix | deterministic | A0 |
| `N-PREFIX-NOT-IN-TABLE` | P0 | must_fix | deterministic | A0 |
| `N-PARAM-EMPTY` | P0 | must_fix | deterministic | A3 |
| `N-PARAM-BAD-VALUE` | P0 | must_fix | deterministic | A3 |
| `N-PARAM-UNKNOWN` | P1 | must_fix | deterministic | A3 |
| `N-PARAM-MISPLACED` | P1 | must_fix | deterministic | A3 |
| `N-SEC-NO-NUMBER` | P1 | must_fix | deterministic | A2 |
| `N-SEC-DUP-NUMBER` | P0 | must_fix | deterministic | A2 |
| `N-SEC-GAP` | P2 | confirm | heuristic | A2 |
| `N-SEC-SCATTERED` | P0 | must_fix | deterministic | A2 |
| `N-SEC-NESTED` | P0 | must_fix | deterministic | A2 |
| `N-IND-NO-CAROUSEL` | P0 | must_fix | deterministic | A4 |
| `N-IND-CAROUSEL-AMBIGUOUS` | P0 | must_fix | deterministic | A4 |
| `N-NAV-TARGET-MISSING` | P0 | must_fix | deterministic | A2 |
| `N-FIX-FROM-MISSING` | P0 | must_fix | deterministic | A2 |
| `N-MODAL-INLINE` | P1 | must_fix | deterministic | A7 |
| `N-SCROLL-NO-TRACK` | P1 | must_fix | deterministic | A5 |
| `N-KV-SINGLE-LAYER` | P2 | confirm | heuristic | A1 |
| `N-IMG-FILL-NO-NAME` | P1 | must_answer | heuristic | A1 |
| `N-TEXT-FIXED-SIZE` | P2 | confirm | heuristic | A6 |
| `N-NAME-DUPLICATE` | P1 | must_fix | deterministic | A1 |

`N-NAME-DUPLICATE`：同一体检根内，两个不同图层用了完全相同的名字（含前缀与 body）。§0 已定「命名才是资产身份的来源（假定 A1）」——两个资产同名，下游按名字取用时无法确定拿到哪一个，切图会互相覆盖、引用会指向错误对象。判定范围是同一体检根内的全部已命名层，不含 `ref/` 子树与 `COMPONENT_SET` 的直接子层（那些名字由 Figma 变体机制强制为「属性=值」，不是资产名）。改法是给其中一个换个能区分它们的 body，不是加数字后缀了事——`img/头像-1` 与 `img/头像-2` 若指的是两组不同列表里的头像，编号并不能说明它们是什么。

`N-IND-NO-CAROUSEL` 与 `N-IND-CAROUSEL-AMBIGUOUS` 只对实际使用现场的 `ind/` / `switch/` 做 A4 联动判定。`COMPONENT` / `COMPONENT_SET` 定义本身是库资产、没有页面上下文，因此不参与这两条联动判定；但它们的前缀语法仍照常检查，定义内部的实例也照常按作用域判定（假定 A4）。

`N-IMG-FILL-NO-NAME` 的适用范围按**最近语义前缀**收窄：当带图像填充的叶子最近前缀是 `ind/` 时不报，因为指示器组件已经承载了内部点状构件的资产身份；`ind/` 内部的图像是同一视觉图形被重复实例化，不需要每个叶子再声明 `img/`。这不是祖先链豁免：若 `ind/` 内部的叶子最近前缀是 `btn/`（或其它更近语义前缀），仍按最近前缀规则报错；本条不扩展到 `btn/`、`switch/`、`tab/` 等其它控件类前缀（假定 A1）。

`N-FIX-FROM-MISSING`：`fix/` 写了 `@from=N`，但体检根子树里没有编号为 N 的 `sec/`。下游按这个号决定从哪一屏开始钉视口；靶不存在时层会一直不出现，或被当成进页就钉（假定 A2）。改成实际存在的分区编号，或补上那一屏。`@from` 只挂在 `fix/` 上，不要写在里面的 `btn/`；它也不是 `@sec`——`@sec` 是点了滚到哪一屏。

## §7 豁免机制（C1 / C2 已实现，C3 未实现）

体检结果里「必须回答」与「只是提醒」两类会反复出现同一批判断。豁免机制让人**判断过一次就沉淀下来**，下次自动折叠。

六条底线，缺一条豁免就会退化成「把报警一条条按掉」：

| # | 底线 | 防什么 |
|---|---|---|
| 1 | 豁免条件只能用限定的字段与写法，且**必须包含至少一个结构性字段**（是否在组件实例内 / 最近的前缀祖先），不能只由尺寸、比例这类连续数值构成 | 「最大边 < 10000px」形式上也是条件，实际等于关掉规则 |
| 2 | 建立豁免时必须显示它在当前稿上命中多少条 | 让「这条豁免有多宽」当场可见 |
| 3 | **`must_fix` 的规则不允许豁免**，只有 `must_answer` 与 `confirm` 能开 | 「必须改」能被豁免，「必须」就是假的 |
| 4 | 命中数按「文件 × 组件 × 规则」去重：一个豁免模式在一个组件上不管中多少条都算 1 次 | 高复用组件（真稿里一个 `bg/pc` 独占 40 条）的噪音会被当成普遍规律 |
| 5 | 判断豁免是否该升级成规范条文时，数**豁免模式的组数**，不数原始条数 | 同上 |
| 6 | 单条规则被豁免比例超阈值时报警；每条豁免带过期时间，过期后**显式回到「待复审」并重新报出**，不静默消失 | 一条规则 90% 被豁免说明规则错了；不写清过期行为就等于永久豁免 |

可用于构造条件的字段：节点类型、最近前缀祖先、是否在组件实例内、尺寸区间、名字形态（Figma 自动名 / 带数字后缀）、同级兄弟中带前缀的比例。Export 勾选不属于豁免条件字段：它不是资产契约。

名字形态 `namePattern` 只取一个值，按下表判定：

<!-- NAME_PATTERNS -->
| 值 | 判据 | 优先级 |
|---|---|---:|
| `figma-default` | 先剥掉尾部的「拷贝/副本」（可带数字），再去掉名字尾部的「空白 + 数字」后，剩下的词（trim、转小写）在 `NON_PREFIX_WORDS`、`FIGMA_DEFAULT_COMPOUND` 或 `FIGMA_DEFAULT_CN` 里 | 1 |
| `numeric-suffix` | 名字匹配 `/[\s_\-]\d+$/` | 2 |

优先级数值越小越优先；同一名字同时满足两项时取 `figma-default`。

<!-- FIGMA_DEFAULT_COMPOUND -->
`mask group`

`FIGMA_DEFAULT_COMPOUND` 只服务 §7 的 `figma-default` 名字形态，不并入 §4.2 的 `NON_PREFIX_WORDS`。§4.2 那张表服务前缀语法判定，键是「斜杠前的单个词」；`parse.mjs` 的前缀正则只捕获 `[A-Za-z]+`，复合词在那里永远匹配不上。若混进 §4.2，就成了死条目，还会让后来人误以为扩那张表能影响前缀判定。两张表的键形状不同，必须分开。

<!-- FIGMA_DEFAULT_CN -->
`矩形` `椭圆` `多边形` `星形` `直线` `箭头` `矢量` `向量` `组` `编组` `框架` `画板` `联集` `并集` `减去顶层` `交集` `排除` `蒙版` `蒙版组` `组件` `实例` `切片` `布尔值` `图片` `图像` `文本`

`FIGMA_DEFAULT_CN` 只服务 §7 的 `figma-default` 名字形态，同样不并入 §4.2 的 `NON_PREFIX_WORDS`。前 23 个词与英文表逐项对应，有互证；最后 3 个（图片/图像/文本）没有英文对应项，依据是实测计数（三份裸稿「图片」26 处）。扩表时必须写明依据是「英文表对应项」还是「实测计数」，不许只凭直觉加词。

条件字段 `nearestPrefix` 的值是字符串数组，匹配语义是：finding 的**最近前缀祖先**属于条件给出的集合，即 `condition.nearestPrefix.includes(finding.context.nearestPrefix)`。普通无前缀容器不改变最近前缀；若 `scroll/` 下又出现 `btn/`，其内部图层的最近前缀是 `btn`，不会被 `nearestPrefix: ["scroll"]` 扩大豁免。

`siblingPrefixRatioLt` 字段保留在 schema 中，但**尚未实现**；匹配逻辑遇到该字段必须显式抛错并指向 §7，不得静默当作恒真或恒假。
