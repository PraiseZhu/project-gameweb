状态：✅ 已定（2026-11-13）

## 已定边界，不重复确认

- 规范未覆盖的情况停止并上报，不自行发挥：P6、2.4。
- 页面数值来自清单，不能目测补布局：P8、第 0 项。
- 公共组件接入口、提示条等已有固定规则的内容，按对应规范处理；不能把“稿上没画”一概当成缺稿：6.4、9.9。
- 外语文案和字体按已定本地化流程与字体声明处理，不因没有独立外语稿而认定缺稿：第 10、11 项。
- 网络失败、素材下载失败等是第 15 项的运行或加载异常，不等于设计没提供。

## 14.1 设计稿提供什么，页面制作什么（✅ 已定 2026-11-13）

正常流程是：设计稿提供页面范围和视觉内容，Gameweb 按设计稿制作对应页面。设计稿是页面形态的来源，不能把“没提供”变成让 AI 自己补设计的理由。

已定规则：

1. 制作前先核对约定的页面范围和所需设计稿是否齐全。
2. 设计稿有的内容按稿制作；设计稿明确没有的内容不生成；不得凭经验补模块、补弹窗、补另一端布局或补装饰。
3. 约定范围内缺少必需设计稿、页面状态、组件外观或端的稿件时，制作在开始前停止并报告缺什么、影响哪一页；不出局部页面，不打 ready，不把已有部分当作完成交付。
4. 如果用户明确把范围改成只做已有的一端或已有的模块，那是范围变更，不属于“缺稿继续制作”；范围变更后按新范围重新核对。
5. 缺稿补齐后重新出清单并从头走对应检查；不沿用缺稿期间的猜测或临时补画。
