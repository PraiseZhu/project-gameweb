## 0. 已经定下的边界，不重复讨论

- 交付物是原生 HTML／CSS／JS 静态目录，有静态 DOM、无需构建；Gameweb 负责设计内容与既定页面能力，开发负责正式配置、组件接入、业务数据、部署、缓存及线上验收。
- 本仓只处理已规范稿与 ready 交接；未规范流程已废弃，不恢复自动命名，不转去别仓，不写回 Figma、不另做插件交接。
- 以设计清单为内容与几何来源，缺必需稿件先停；不让 AI 猜模块、交互目标、动效或缺失数值。HTML v1 不代表现有 ready 内容已足够支撑所有新要求。
- 本次实际需要几种语言就覆盖几种；不固定五语、不补无需求的端别或功能。
- 已定交互行为、动效分类／参数、字体／图片／体积要求不重新当作开放选项。待定的是数据怎样补齐、如何生成、在哪检查、怎样留证据。
- 交互信息补齐与动效设置分开：前者归 F1，后者归 F18。不要再引入“简单／复杂交互”分类来扩展议题。
- 交互验收先程序白盒、后人工黑盒，两道均通过；具体工具和操作方式后定。标准定稿不等待校准，具体页面交付仍需证明达标。
- 任何候选 @motion、@sec=next、新模块前缀、nodeId 面板等，不能因本文件出现而视为现行工具已支持。

## 1. 命名、清单和交互信息（F1～F9、F12～F15）

### F1 模块身份与交互信息补齐

**已定：** 模块有明确身份，网页 class 与模块对应；用途说明复用按钮的动作／目标，不另外猜一份语义。交互关系不明确不能验收通过。

**待讨论：**

- 模块类型与现有角色前缀怎样统一，英文短词、中文备注、同名结构及变体如何进入清单；网页名按“英文短词-类型”的原则保留。
- 模块同时可点击时怎样表达，避免前缀冲突；复制等原有参数未覆盖的动作怎么声明；导航／TAB 选中底图与状态词怎样明确。
- 每个交互节点“做什么、作用于谁”的信息缺口在哪一步补、由谁补、怎样绑定具体模块与保存。命名、结构、配置或界面均待讨论，不预选其中一种。
- 已有明确命名参数怎样复用；结构关系怎样只在唯一、无歧义时采用；怎样发现缺动作、多候选或重名目标，而不是按位置／输入顺序猜。
- 同一份已明确语义怎样供 data-* 接线、用途说明和白盒验收使用；重拉稿件后如何核对它仍对应原对象。

**已知缺口：** 2026-11-16 的伊瑟源码及内存结构验证发现，同级多个 switch 的一个查找分支取首个候选，交换输入顺序会改变目标；btn/ 身份明确也不等于动作明确。本轮未重验或修复该代码，不推断所有页面均受影响。

**讨论后应留下：** 模块／交互信息合同、缺失与歧义的报告方式、负责补充的人及所在步骤。不得只产出脱离页面模块的按钮名单。

来源：items/00、04、09、17 的 17.7b；关联 F2、F3、F6、F12～F15、D2、D5、D6。

### F2 重复项的明确标识

- 已定：同类重复项需确定标识，不靠外观相似判断；同名模块外壳相同，内部差异由子模块／变体表达。
- 待讨论：重复容器、模板项、固定槽位与可增减列表的具体写法及清单字段；如何与组件复用、接口列表和同名结构校验配合。
- 产出：重复项标记及抽取／消费合同。不能把“同母版”自动等同于“后台会增减”。

### F3 PC 与手机的对应关系

- 已定：两端对应模块要明确关联，不能让 AI 根据画面猜；各端几何和素材取各自稿件。
- 待讨论：同名对应怎样记录；两端结构差异怎样表达；只做一端时如何保持实际范围，不要求补另一端。
- 产出：跨端身份与差异的对应合同，供 DOM 组织和断点切换使用。

### F4 命名、清单与做页的改动归属

- 2026-11-17 已确认：本次新流程在独立的 one-page标准流程分组推进，现有游戏项目保持独立；复用公共工具或迁移旧项目的具体范围另行确定。
- 已定：命名／清单由 standards/figma-naming 管，做页消费清单；本侧不直接维护同事负责的 yise-web-ui。
- 动手前待核实：旧的“[replaceable] 由另一会话修改，本侧暂不动规范／解析器／字段”是否仍有效；当前并行工作和改动归属是什么。
- 待讨论：新字段怎样衔接现行 inventory/v2、ready 包及消费者；哪些变更只在标准工具，哪些需交同事；相关规范、速查和测试如何同步。
- 产出：明确改动范围、交接内容和负责人；不能据本文自动改两个游戏 Skill、提交 Issue 或派工。获准交接时再按既有协作约定执行。

### F5 自动布局信息补齐

- 已定：会增减的组必须有自动布局依据，固定组可取已有坐标；方向、间距、对齐、内边距、换行不靠猜。
- 待核实：实际稿件哪些组已使用自动布局；清单当前抽取哪些字段，哪些缺失。旧观察不能代替新一次检查。
- 待讨论：按接口列表／开关、地区配置、重复标记识别可增减组的具体检查；缺自动布局怎样报错；字段如何保存及生成 flex／grid 排布。
- 产出：自动布局字段合同、缺失处理和动态收拢的验证方式。关联 C2、D1、D3。

### F6 接口内容标记与字段合同

- 已定方向：在设计稿声明接口内容，分开关、列表、字段，并覆盖状态字段；标在最近承载层。字段名与接口一字不差，子层相对路径由外层组合，不另造第四套语法。
- 待讨论：复用前缀／方括号／@ 参数中的哪一种具体写法；如何与模块／重复项统一，如何区分固定槽位、可增减列表、图片字段与状态字段。
- 待对接：只取影响页面生成的字段规范、JSON 样例、语言／列表／开关约定，以及会限制页面字段安排的能力说明。后台名称／入口、权限、配置建立、发布与生效操作不列为 Gameweb 当前资料需求。暂按设计字段先定，有开发正式字段约定则据其明确调整。
- 待讨论：字段表如何汇总和交开发，如何核对名称／类型／语言结构、标记与字段不匹配、数据范围变更；不以正式名单／比分发布为设计侧前置。
- 产出：标记、清单字段和数据说明之间的对应合同。关联 R8～R11、C2、D3。

### F7 前景装饰的统一标识

- 已定：前景是明确的独立装饰身份，不等于全部图片；页面遮挡仍按稿，弹出层例外。
- 待讨论：现有“前景装饰／前景素材／装饰前景”等不同写法如何统一，两端怎样对应，清单如何表达。
- 产出：一种一致的身份表达与消费方式；不能凭名字里的“前景”强制抬到正文上方。关联 F18、C3。

### F8 把命名校验接进出清单

- 已定：模块格式、英文短词缺失、重复类型词、同名不同构等检查应在出清单时执行；不合格不能标 ready。规范与速查站同步说明。
- 已知历史事实：2026-11-12 核查的 npm run inventory 并未执行独立 lint 的完整检查；不能因为工具目录有 lint 就说主流程已经有此门。
- 待讨论：哪些检查在抽取时执行、报错定位与代码、与现有校验的关系、重新出清单后的复验；不以另建 Figma 插件代替。
- 产出：出清单检查范围及失败结果合同。关联 F1～F7、F13、F4。

### F9 核对页只读与错误回改

- 已定方向：已规范稿核对页只查看，不保存手改清单；发现错误改设计稿、重新抽取，不能形成第二份手工真源。
- 待讨论：核对页应展示哪些证据、如何定位错误，怎样区分仅查看与确认结果；现有保存 reviewed.json 的历史能力如何处理。
- 产出：只读核对与回改重跑方式。不得恢复已废弃的未规范稿自动命名／人工改 draft 流程，也不写回 Figma。

### F12 下一屏按钮的标识

- 已定行为：到下一个可见屏，末屏变为返回首页；既定轻跳和固定块显示规则不变。
- 待讨论：如何明确该动作及其页内唯一性；@sec=next 是历史示意，现行 @sec 收数字，不能直接要求设计师使用未支持参数。
- 产出：与 F1 统一的动作表达和抽取检查，而非新增一套独立按钮体系。

### F13 两种轮播的结构与圆点

- 已定方向：switch 内装 list／重复项的为同款卡片分页，装独立页面模块的为不同内容轮播；混合或缺结构需报告。具体新前缀仍按 F1／F2 统一。
- 已定行为：每页数量按稿，同款卡片页数随条数变化，ind 圆点按实际页数生成，状态 highlight／normal；两种轮播共用已定循环规则。
- 待讨论：如何在命名规范和速查中准确写出结构判定、list 语义及圆点生成；如何避免把 TAB、轮播页与普通容器混认。
- 产出：规范正文／速查／清单消费者一致的解释。此前已要求未来同步，但本次整理不执行修改。

### F14 页码标识

- 已定：有稿才生成页码；多页两位补零，单页可显示 01/01，0 条隐藏。
- 待讨论：如何标识“当前页／总页数”文字、如何绑定唯一轮播、怎样区分固定文案与页码。
- 产出：页码字段与轮播关系，合并到 F1，不新增第二套绑定方案。

### F15 空状态与列表的关系

- 已定：0 条只显示已定义空状态，不能用示例数据充数；不显示卡片／箭头／圆点／页码。
- 待讨论：空状态如何绑定具体列表或轮播，其中文字和图片如何分别保留；缺空状态稿或关系不明确时如何报告。
- 产出：空状态身份与目标关系。已有 img/空状态 名称本身不证明对应目标已知。

## 2. 生成、预览和设置入口（F10、F11、F16～F18）

### F10 三个公共组件接入口怎样生成

- 已定：页脚在最后一个可见屏，背景视频在首屏，埋点在 head 预留接入位置；存在才调用，不在则跳过。具体成品形态已写入 HTML v1 第 7.2 节。
- 待讨论：挂载 DOM、配置、衔接代码和未启用脚本位置怎样由生成器输出；如何验证缺组件时不报错、不请求不存在文件，接上后按既定方式工作。
- 资料边界：按 HTML v1 已定接入口生成，正式页脚、背景视频、埋点组件及其源库不列为当前待提供素材。实际流程讨论发现接口合同不足时，只说明影响挂载或衔接代码的具体缺口，再补对应说明。
- 产出：接入口生成和验证方法；正式组件的实际接入和生产参数仍由开发后续处理，不因此让 Gameweb 先接入或触发统计。

### F11 QA 设备预设

- 已定：沿用 18 种适用视口加 1024／1025 往返，实际尺寸清单在 HTML v1 第 5 节；只放 QA 外壳，不进产品页。
- 待讨论：预设入口和显示方式、如何切换当前实际端别、检查状态如何记录；不增加未经确认的浏览器版本或设备范围。
- 产出：QA 视口检查操作及证据记录，关联 C1、C3、C5。

### F16 实际语言范围与独立页面输出

- 已定：语言数量按项目；QA 外壳验语言，不增加产品菜单语言预览。验收后从同一份结果输出独立 HTML，正式网址开发后填。
- 待讨论：实际语言集合在哪声明、本地化来源怎样关联、生成／拆分顺序、修改后怎样保证语言结果同源；仅一语如何简化而不报缺其他语言。
- 待核实：现有工具对本次语言的支持范围，不从“语言不定死”推断已支持任意新语言。
- 产出：实际语言、文案、语言素材、字体与输出 HTML 的一致范围；交付前不单独手改某一种语言成品。

### F17 字体声明与字体资源

- 已定：简中取稿，其他实际语言按角色声明；真实字重、完整字库、来源／许可齐全。缺字体先报告，未使用字体不进包。
- 待讨论：声明表放在哪、由谁填、如何读取和验证；字体登记册与页面声明怎样衔接；现有写死的伊瑟字体路由如何迁移为项目声明。
- 产出：声明和登记合同、加载与打包验证；不把具体伊瑟字体写成所有游戏默认。关联 D7、C4。

### F18 设置动效

- 已定：六类动效及已列参数；正文随所属模块，逐项／分批与整组模式不同，PC／手机保留各自明确参数，不猜未覆盖值。
- 待讨论：在哪一步、哪个入口设置，选择粒度是什么，如何绑定模块、保存并进入清单；怎样表达父子／多模板冲突、隐藏内容、重播与减少动画等已有约束。
- 尚未批准：@motion 参数、出清单前固定面板、按 nodeId 点选绑定的具体界面，以及“没设置就不播”的默认策略。
- 产出：动效选择与数据传递方案、缺失／冲突提示；不重定已确认时长曲线。关联 F1 的模块身份，不与按钮动作补齐混为一项。

## 3. 校准与验证（C1～C5）

### C1 底图／盖层位置验证

- 已定要求：盖层钉所属模块，不被文字推走；各端分别取清单，文字超长在模块内处理。
- 既有验证目标：适用语言与视口下，盖层／底图相对位置换算回稿误差 ≤1px；既有重点视口为 1280×720、1920×1080、2560×1080、375×812 及断点两侧，结合已定布局范围使用。
- 待讨论：选什么真实样本、怎样量和记录；设计稿才是几何真源，开发样本存在差异时不能为对齐旧页改设计数据。像素检查方法归 C5。

### C2 后台默认值过期

- 已定：HTML 有默认内容，后台数据成功时覆盖；失败回默认，示例结果显示“待公布”。不改成后台直接重写 HTML 的新发布系统。
- 已知风险：后台日期／奖金等更新后，静态默认值未同步，网络失败会显示旧内容。
- 待讨论：哪些值需要保持一致、由谁维护、何时同步与重新交付、怎样暴露不一致；后台维护归开发，不把其发布步骤移给 Gameweb。
- 产出：默认值维护边界与检查方式。关联 F6、D3、R9～R11。

### C3 前景层级差异验证

- 已定：画了的层级按设计顺序，弹出层最上；不照搬开发把前景统一设高的做法。
- 已知样本差异：开发前景曾放 z-index 60，部分高于导航／正文，设计中对应装饰位于内容之下。
- 待讨论：怎样证明各端各屏遮挡、透明边缘和点击区域正确，怎样记录有意保留的设计差异；不能为追求“开发样本全绿”改规则。

### C4 素材画质、格式与编码验证

- 已定：PNG 源直出 WebP，实际透明无损、不透明 q90／method6；不缩尺寸／裁切，不串联旧有损图。完整字库和历史素材保留要求不变。
- 已定 SVG 判定原则：检查完整可见绘制边界及依赖；图片填充／位图走 raster。纯矢量路径、布尔、矩形、椭圆、多边形、星形、直线，以及仅容器的 frame／group／component／instance 可进入 vector 候选，已验证渐变填充／描边可候选；live TEXT、复杂遮罩、滤镜、模糊、混合或未验证效果退位图并记录原因。
- SVG 从 Figma 导出后须无 image 嵌入／外部依赖、导出框正确，并与 PNG 基准保持画面；失败回 PNG→WebP，无法建立基准则停。结构读不全是 unknown，不能当“没有位图”；不擅拆 img/ 边界。
- 待讨论：由哪个环节导无损源图、分类与验证、实际 alpha 扫描、编码版本与记录、最终 Pack 如何避免再次有损编码或 q70 覆盖已定 q90。
- 待讨论：逐图比较引擎、色彩解释、SSIM／PSNR 等阈值、透明边缘底色、样本覆盖和人工画质检查；无损 alpha／可见 RGB 要求已定，不拿整屏 6% 代替逐图检测。
- 产出：素材制作与画质证据链、异常报告、manifest 记录及最终素材回验方式。不是重开图片格式或在本版发明数值门槛。

### C5 整页检查、像素门与总校准

- 已定：成品符合设计，内容、字体和交互独立检查；程序白盒先过、人工黑盒再过；当前页未跑不能拿包级单测冒充已验收。
- 既有起点：当前逐屏像素门与 6% 差异上限只作流程校准起点，不表示“94% 还原度”，也不是 HTML 格式标准。最终阈值与执行方案留本项。
- 资料输入：开发已有验收方法、工具、覆盖与报告（R7），包括是否有截图对比；已有 README 记录可复用，缺失部分请开发说明，不能直接写成“他们没有”。
- 待讨论：参考稿／语言／视口／静态状态、截图时点、缩放和字体等待、比较引擎、遮罩及基准缺失处理；逐屏和差异图怎样记录，不能让全页平均掩盖单屏问题。
- 待讨论：结构、资源、字体、交互状态、视口、内容保护与减少动画等既定检查怎样组织；白盒测试数据和人工操作报告如何绑定同一页面版本。
- 待讨论：缺基准／读取失败／跳过／未执行的结果如何显式报告，失败从哪一步回改复验；无需先让开发原样本满足所有设计侧调整。
- 产出：真实页面的验收执行方法和报告，不把制作参数、工具校准回写成 v1 未定稿。
