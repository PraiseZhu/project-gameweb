## 这份文件为什么存在

本项目**不生成页面、不产出切图、不产出文案表**。所以「命名错了会有什么后果」这件事，本项目自己无法观测——没有下游实现可以拿来验证。

如果不写下假定，每条规则的「不改会怎样」就只是沿袭旧经验的信念。写下来之后，它们变成**「在以下假定成立时必然如此」的推论**——仍然不是被观测证实的事实，但至少前提是显式的、可被反驳的、可以随假定一起改的。

**每条规则必须引用至少一条假定**（`rules.mjs` 的 `assumes` 字段），引用不存在的假定编号会导致测试失败。

假定被证伪时的处理：改这份文件 → 漂移测试红 → 同步同目录 `spec.mjs` 的版本号 → 重新评估引用它的那些规则是否还成立。

## A0 · 前缀语法

下游按**大小写不敏感 + 半角或全角斜杠**匹配前缀，斜杠两侧允许空格。`IMG/` 与 `img/`、`img / 装饰` 与 `img/装饰`、`img／装饰` 与 `img/装饰` 同义。

**反斜杠 `\` 不匹配**，带反斜杠的名字按「无前缀」处理，不被识别为任何资产/交互意图；工具会对它报 `N-PREFIX-SLASH`，提示改成半角 `/` 或全角 `／`。

**总表外的词**同样按「无前缀」处理，工具报 `N-PREFIX-NOT-IN-TABLE`（§4.3），防止设计师以为标了、实际等于没标。

## A1 · 切图消费

下游按 `img/` `bg/` `kv/` 命名前缀识别并导出栅格资产。Figma 的 Export 勾选只是人工导出设置，不是资产身份契约；本工具不据此推断切图意图。

**命名是资产身份的来源**——资产在下游被引用的标识来自图层名。Export 可覆盖格式与倍率，但不承担身份，也不改变前缀判定。

**带图像填充的叶子节点即使没有任何前缀也会被当作候选资产**（下游不会把一张位图当作可代码复现的元素），同样地，它的标识只能由结构位置推断。

**`ind/` 组件承载指示器点状构件的资产身份**：`ind/` 内部的图像叶子是同一视觉图形在多个指示器实例中的重复构件，不需要每个叶子再声明 `img/`。这条边界只在 `ind/` 是最近语义前缀时成立；如果 `ind/` 内部还有更近的 `btn/`、`switch/`、`tab/` 等语义前缀，资产身份仍按最近前缀的规则判断，不能把例外扩成所有控件类前缀。

**`kv/` 的多层用于视差**：同一父层下的多个 `kv/` 被叠层摆放并按 `@parallax` 系数走不同速度。只有一层时视差无从体现。

结构节点（带分区、交互、滑动、切换语义的层）被整块导出时，内部结构在栅格化过程中丢失，无法恢复。

## A2 · 分区消费

下游在**体检根子树内**搜集所有名为 `sec/<编号>-<名称>` 的 frame，按编号竖排成滚动页。中间没有识别前缀的纯布局容器（`FRAME` / `GROUP`）是透明的，不改变分区归属；编号仍是排序与跳转的唯一依据。

分区流真正会出错的情况，以及可观测后果：

1. **各 `sec/` 不在同一逻辑父层**（忽略纯布局容器后）：竖排不再是单一序列，两组之间的交错顺序没有定义，下游可能把页面顺序排错，导航跳转也无法稳定对应。
2. **`sec/` 嵌在另一个 `sec/` 内**：内层分区归属二义，编号排序无法形成唯一的页面流，`@sec=N` 可能落到错误层。
3. **`sec/` 的祖先链上有带语义的前缀**（包括 `img/`、`bg/`、`kv/`、`switch/`、`tab/`、`modal/` 等）：切图类祖先会整块栅格化并丢失分区结构；切换器、页签条、弹窗里的内容也不是页面分区，分区归属会被下游错误消费。
4. **`fix/` 写了 `@from=N` 但没有编号为 N 的分区**：下游按这个号决定从哪一屏开始钉视口；靶不存在时层会一直不出现，或被当成进页就钉。`@from` 不是 `@sec`——后者是点了滚到哪一屏。不写 `@from` 则进页就钉。

## A3 · 交互与参数消费

`btn/` `hot/` 生成可点击区域。点击后的行为由参数或外部配置提供——**本工具不要求动作必须写在图层名里**，只在参数存在时校验它的取值与位置。开弹窗时 `@go` 抄弹窗图层名（`modal/顶部导航`），不要写 node id；同名弹窗无法唯一对应。

**本条覆盖全部 `@参数`**，不只交互类。每个参数的语义由它所属的消费方定义：

| 参数 | 语义归属 |
|---|---|
| `@link` `@go` | 本条（交互） |
| `@sec` | A2 分区消费——滚动到该编号的分区 |
| `@from` | A2 分区消费——`fix/` 从该编号的分区起钉视口 |
| `@parallax` | A1 切图消费——视差系数 |
| `@x` `@y` | A5 滑动消费——滑动方向 |

三条参数消费的通则：

1. **不在参数表内的参数被整个忽略**，不产生任何提示，声明的意图静默丢失
2. **参数挂在不支持它的前缀上一律无效**，同样静默
3. **取值越界不会报错**，而是让对应的消费行为失真——`@sec` 指错分区、`@from` 从错误屏开始钉、`@parallax` 视差计算异常、纯标记带值被当作未知参数

## A4 · 联动消费

`switch/` 是切换器 / 轮播容器，`tab/` 是它的页签条，`ind/` 是进度指示器。

指示器的序号按**同级顺序**推定，因此同组指示器允许同名。指示器与被切换内容的关联在一个作用域内确定：作用域是 `ind/` 最近的 `sec/` 祖先；如果没有 `sec/` 祖先，则作用域是体检根。作用域内的纯布局容器透明，`switch/` 候选要在该作用域的整棵子树内搜集，不能跨到别的 `sec/`。

判定按以下顺序解释作用域里的结构，并对应可观测后果：

1. **`ind/` 的祖先链上已有 `switch/`**：关联对象已经由嵌套关系唯一确定，不会产生联动定位问题；即使作用域内还有其它 `switch/` 也不构成二义。
2. **作用域内没有 `switch/`**：指示器没有任何可绑定的轮播对象，点击圆点不会驱动内容切换。
3. **作用域内有多个 `switch/`，且 `ind/` 不在任何一个内部**：关联对象出现二义，下游可能把圆点绑定到错误的轮播，导致点击后切换错内容；另一个分区里的 `switch/` 不属于本作用域，不能拿来消除这种二义。

**组件定义边界（D6）**：`COMPONENT` / `COMPONENT_SET` 本身是库资产，没有页面上下文，不参与上述 A4 联动判定。一个 `ind/` 定义可以在不同实例里分别放进不同的 `switch/`，直接追问「这个定义绑定哪个轮播」没有答案，也无法指向可观测的页面后果。该边界只豁免联动判定；组件定义自身的名字仍按 A0 的前缀语法判定，组件定义内部的实例则按它们在使用现场的作用域照常判定。

## A5 · 滑动消费

`scroll/` 容器是视口，它的**第一个子层**是内容轨道，轨道的直接子项是列表 item。容器内没有子层则产不出 item。

轨道内部的图像仍需命名——它们是要被切成资产的内容，不因为在轨道里而豁免。

`scroll/` 写在 `mix/` 里面时，滑动裁切身份不变：视口仍是 `scroll/`，第一个子层仍是轨道。外层 `mix/` 不把整块栅格化，也不把 `scroll/` 降成普通切图。

## A6 · 文案消费

TEXT 节点**默认**即可配置文案，不需要前缀声明——无前缀的 TEXT 是**可改文案**，改字即可换内容。

**名字压过类型：** 一旦 TEXT 挂了视觉类前缀（`img/` `bg/` `kv/`），它按**切图**消费，不再当作可替换文案——`img/标题字` 是美术字切图，文字内容只是图形的一部分。前缀声明的是这个节点的资产身份（假定 A1），不是文字语义。

**本工具不规定文案 key 如何生成**，那是下游的事。A6 前半句（文案不得烙进栅格资产）目前无规则检测：`N-TEXT-IN-SLICE` 于 v2.6 退役，因为它把「切图节点内有 TEXT」当作「文案被烙图」的代理，而按前缀定义这个代理在结构正确的稿子里恒为假；候选替代规则「切图节点内部含非视觉类前缀」真稿命中 0，无证据不加。

文案尺寸分两档：紧凑控件（TEXT 的祖先前缀链含 `btn/`、`tab/`、`switch/`、`ind/`）按定宽定高还原；长段落按定宽自动换行还原。独立段落不因固定尺寸本身报警。

## A7 · 弹窗消费

`modal/` 是独立 frame，不参与页面正常态的分区与层序。画在页面稿内的 `modal/` 会成为页面内容的一部分。

## A8 · mix 自动拆切图

`mix/` 是图文混排容器，不是切图角色。下游按容器的 `role=mix` 保留结构；**不整块导出** `mix/` 本身。

设计师只命名这个容器。清单在编 `inventory/v2` 时自动拆切图出口：

1. `mix/` 子树里带图像填充、且没有自己前缀的叶子升为 `determined` `img/`（`via=structure`），并写 `sliceExport`。做页按这份契约导图，不得去猜 `skipped` / `art-fragment` 子层。
2. 无前缀 TEXT 仍按 A6 当可改文案，不烙进切图。
3. 叶子已有自己的前缀（`img/` `bg/` `kv/` `scroll/` `btn/` `dyn/` 等）时，身份以该前缀为准，不因外层 `mix/` 改写。
4. `scroll/` 写在 `mix/` 里时仍按 A5：滑动裁切继续生效。设计师给「可滑动内容」加 `scroll/` 前缀，与清单自动升格同义。
5. `mix/` 子树里无自己前缀、打开了裁切、且子层或自身相对父层横向溢出的 FRAME/GROUP，升为 `determined` `scroll/`（`via=structure`）。这是滑动视口，不是整块切图。
6. `BOOLEAN_OPERATION` 的 `btn/` 保持 click，同时写 `sliceExport`；子层是 `slice-child`。导按钮合成形，不要给 Subtract 零件加 `img/`。
7. 页上用到的 `ind/` 组件集，每个变体 `COMPONENT` 根保持 indicator，同时写 `sliceExport`；零件是 `slice-child`。导变体合成形，不要给小钻石加 `img/`，不要用 CSS 菱形。做页按实例 `componentId` 消费对应变体 PNG。
8. 页上用到的 `img/` 组件集，仅当变体属性名是 `lang`、且至少有两个不同的精确小写 `cn` / `tw` / `en` / `jp` / `kr` 变体时，这些合法变体 `COMPONENT` 根保持 slice，同时写 `sliceExport`；零件是 `slice-child`。导的是该语言合成形。没有 `lang` 轴、只有一个变体、`CN` / `xx` 这类非精确小写五码、`Property 1=cn` 旧写法当普通图，不跟页面语言。未画的语言不做出清单失败条件；做页切到缺变体时 fail-visible，不回落 `cn` 图。页面语言 key 仍是 `zh-CN` / `zh-TW` / `en` / `ja` / `ko`，映射到上述五码；`region=cn` 是国服。

## 明确不在假定范围内的

- 文案 key 的生成规则、命名风格、稳定性保证
- 切图边界如何划定、一块视觉该拆成几张资产（A8 只保证 `mix/` 下带图像填充的叶子有切图身份，不规定格子是一张还是多张）
- 交互的具体实现方式（CSS 还是状态机、预载还是懒载）
- 任何与视觉品质、设计意图相关的判断
