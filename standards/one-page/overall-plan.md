# one-page 整体方案（当前有效版）

更新日期：2026-11-20。A～H 各阶段方案均已获用户确认（见讨论记录 R034/R036、R181、R199、R212、R217、R220），并按 R221～R224 的解耦修订更新；各环节职责见 [stage-responsibilities.md](stage-responsibilities.md)。本文件只汇总当前有效口径，各阶段细节以对应文件和讨论记录为准。它是方案，不代表工具已实现或任何页面已通过。

## 1. 目标

设计师给一份已规范命名的 Figma 页面，流程产出符合[最终页面标准](delivery-and-acceptance.md)（H01～H43、A01～A12）的静态 HTML 交付包，交给开发接手。独立建设，不依赖开发内部 Skill，但不猜页面必需的输入。

## 2. 流程总览

A 范围确认 → B 输入整理与交接包 → C 单语言完整页面 → D 第一次验收 → E 多语言制作 → F 第二次验收 → G 最终包核对 → H 冻结交接。

只有一种语言时跳过 E/F，D 确认后直接进入 G。

## 3. 各阶段要点

| 阶段 | 做什么 | 通过条件 | 详细方案 |
|---|---|---|---|
| A | 只确认四件事：Figma 页面链接、实际语言、基础语言、端别（电脑/手机/双端） | 链接可访问且是规范稿，范围明确，用户点了确认 | [SKILL.md](SKILL.md) |
| B | 从稿里读取确定的事实，只补稿里定不了的：外语字体、组件状态和动作、数据字段、动效、译文和外语素材；编成一份可追溯的交接包；改稿时只出变化交接包 | 当前范围检查全部通过就自动交 C；有缺失或冲突就停下并指出位置 | [b-input-handoff-plan.md](b-input-handoff-plan.md) |
| C | 用交接包制作基础语言、约定端别的完整页面：画面、适配、交互、数据缺省、动画代码、压缩；跑全套自动检查（原 D 的 13 类与八项送验合并，含像素门）并自己修到全部通过 | 全套检查全部通过且记录完整，才交 D | [c-page-production-plan.md](c-page-production-plan.md)、[d-automatic-check-plan.md](d-automatic-check-plan.md) |
| D | 不重跑检查，只核对 C 的检查记录；再交设计师在 QA 页面只看真实页面，意见交 C 修，满意后整版确认一次 | 记录齐全且对应当前页面和规则；设计师确认后交出设计确认版 | [decoupling-mechanism.md](decoupling-mechanism.md) |
| E | 以设计确认版为基准做本次其他语言，每种语言一份独立 HTML；跑全套语言检查并自己修完；缺资料只停那一种语言 | 不用中文占位、不自行翻译 | [ef-multilanguage-plan.md](ef-multilanguage-plan.md) |
| F | 不重跑检查，只核对 E 的检查记录；整组交设计师看，意见交 E 修，最后确认一次 | 不逐语言签收；交出与 D 同格式的设计确认版 | [ef-multilanguage-plan.md](ef-multilanguage-plan.md) |
| G | 只读设计确认版，按开发标准打包，在打包后的文件上重新核对，不再压缩或改效果 | 文件、引用、字体、编码、manifest、画面和交互与确认版一致 | [gh-final-package-plan.md](gh-final-package-plan.md) |
| H | 冻结版本，附文件清单、校验值、全程检查记录和开发待办（来自 B、C 记录），交给开发 | 冻结后再改算新版本；设计交付完成不等于正式上线 | [gh-final-package-plan.md](gh-final-package-plan.md) |

## 4. 环节怎样保持独立

- 每个环节只读收到的成果、只写自己的成果；交出时按内容生成版本号。
- 开工前检查上一环已通过、成果完整、版本对得上，否则退回。
- 结束时写统一格式的环节记录：输入版本、成果版本、结果、问题清单（带退回环节）、用到的共用工具、开发待办。
- 环节之间不直接调用，由流程编排衔接：通过进下一环，不通过按问题清单退回；单语言跳过 E/F。
- 自动修复和改稿循环中，同一问题连续两轮没修好或一轮下来问题数没减少就停下报告。
- Figma 读取导出、自动检查、像素比较、QA 页面是共用工具，不算环节。

## 5. 贯穿全程的规则

- 稿上能读到的不再问人；定不了的才补，有冲突不按顺序挑一个。
- 做不到就停下并说明在哪一步、缺什么，不降级、不缩范围、不把没跑的检查当通过。
- QA 只看真实页面，不放设计稿对照；全套自动检查（含像素门）在 C/E 跑完修完。
- 动画实现代码必须符合开发标准，时长、位移、曲线等效果参数后续可调。
- 下载、社媒等外部跳转只留可配置入口，正式链接由开发填写。
- 已完成的页面改稿走点对点修改，只复验受影响部分，不重跑完整流程。
- 优先复用已有出清单、交接包和像素门能力，增量改造，不另建一套。
- QA 工具、清单、交接包、测试数据和检查产物都不进最终包。
