标题：one-page 新流程：已规范 Figma 稿到开发标准静态页交付包（A～H 总 Issue）

## 问题

现有 Gameweb 做页链路按单个游戏各自维护，产出的页面不能稳定符合开发侧的最终页面标准（HTML v1，H01～H43、A01～A12）。需要一条独立的 one-page 流程：设计师给一份已规范命名的 Figma 页面，产出符合开发标准的静态 HTML 交付包，交给开发接手。流程要独立建设，不依赖开发内部 Skill，也不猜页面必需的输入。

## 方案

建立 A～H 八个独立环节，由流程编排串联，每个环节只负责自己的内容，做完交给下一个环节。

### 流程

A 确认范围 → B 整理输入与交接包 → C 单语言完整页面 → D 第一次验收 → E 多语言制作 → F 第二次验收 → G 最终包核对 → H 冻结交接。只有一种语言时跳过 E/F。

### 各环节职责

| 环节 | 负责 | 不负责 |
|---|---|---|
| A 确认范围 | 收 Figma 页面链接、语言集合、基础语言、端别；用户确认后出范围记录；链接无效、不是规范稿、范围冲突时停 | 不问模块、字段、交互等页面内容 |
| B 整理输入 | 读稿上确定的事实；只补稿上定不了的：外语字体、组件状态和动作、数据字段、动效、译文和外语素材；检查后出交接包；改稿时只出变化交接包；缺件语言单独标出；记录开发要填的配置项 | 不导出素材、不做页面 |
| C 制作单语言页面 | 按交接包导素材、做画面、适配、交互、数据缺省、动画代码、压缩；跑全套自动检查（含像素门）并自己修到全部通过；按设计师意见修改；按变化交接包点对点改稿；记录预留入口和未填外链 | 不读交接包以外的需求；稿件版本对不上就停，退回 B |
| D 第一次验收 | 核对 C 的检查记录（齐全、对应这一版页面、当前规则），对不上退回 C；交设计师在 QA 页面只看真实页面，意见交 C 修；满意后整版确认一次，出设计确认版 | 不重跑检查、不改页面 |
| E 制作多语言页面 | 以设计确认版为基准做本次其他语言，每种一份独立 HTML；跑全套语言检查并自己修完；缺件语言暂停 | 不改已确认设计；不自行翻译、不用中文占位 |
| F 第二次验收 | 核对 E 的检查记录；整组交设计师看，意见交 E 修；满意后确认一次，出与 D 同格式的设计确认版 | 不重跑检查、不改页面；不逐语言签收 |
| G 最终包核对 | 只读设计确认版；按开发标准打包；在包上重新核对文件、引用、字体、编码、manifest、画面和交互 | 不压缩、不改效果；有问题退回 C 或 E |
| H 冻结交接 | 冻结版本；汇总文件清单、校验值、全程检查记录和开发待办；交给开发 | 不负责正式上线 |

### 环节怎样保持独立

- 每个环节只读收到的成果、只写自己的成果；交出时按内容生成版本号。
- 开工前检查上一环已通过、成果完整、版本对得上，否则退回。
- 结束时写统一格式的环节记录：输入版本、成果版本、结果、问题清单（带退回环节）、用到的共用工具、开发待办。
- 环节之间不直接调用，由流程编排衔接：通过进下一环，不通过按问题清单退回。
- 自动修复和改稿循环中，同一问题连续两轮没修好或一轮下来问题数没减少就停下报告。
- Figma 读取导出、自动检查、像素比较、QA 页面是共用工具，不算环节。

### 贯穿全程的规则

- 稿上能读到的不再问人；定不了的才补，有冲突不按顺序挑一个。
- 做不到就停下并说明在哪一步、缺什么，不降级、不缩范围、不把没跑的检查当通过。
- 动画实现代码必须符合开发标准，效果参数后续可调；外部跳转只留可配置入口，正式链接由开发填写。
- 已完成的页面改稿走点对点修改，只复验受影响部分。
- 优先复用已有出清单、交接包和像素门能力，增量改造。
- QA 工具、清单、交接包、测试数据和检查产物都不进最终包。

### 推进方式

先做前置项 P0（命名规范与交接工具收尾），再从 A 开始逐个环节推进。每个环节单独发 Issue 挂在本 Issue 下，依次经过：方案讨论与确认 → 实施 → 独立测试、审核、验收 → 关闭，才开始下一个环节的方案讨论。

### 进度

- [ ] P0 命名规范与交接工具收尾
- [ ] A 确认范围
- [ ] B 整理输入与交接包
- [ ] C 单语言完整页面
- [ ] D 第一次验收
- [ ] E 多语言制作
- [ ] F 第二次验收
- [ ] G 最终包核对
- [ ] H 冻结交接

## 验收条件

- P0 与 A～H 各环节 Issue 均已按各自验收条件通过并关闭。
- 用一页真实规范稿从 A 跑到 H，产出符合开发标准（H01～H43、A01～A12）的最终交付包；单语言与多语言路径各至少跑通一次。
- 每个环节都能单独运行，环节记录可从最终包一路追溯到范围确认。
- `skills/yise-web-ui` 与 `skills/torchlight-web` 不因本流程改动。

## 不做

- 不改伊瑟、火炬两套现有游戏 Skill；不写回 Figma。
- 不处理未规范命名稿。
- 不负责正式网址、接口、埋点、部署等上线工作。
- 本 Issue 本身不授权任何环节的开发；各环节开工以各自 Issue 的确认为准。

## 未决项

- 各环节的具体实施方案（改哪些文件、复用哪些工具、验收细节）在对应环节 Issue 中逐个讨论确定。
- 像素门门槛等具体数值在 C 环节实施时校准。
